5. What backend architecture is recommended? A Clean Modular Architecture built inside the Next.js 16 App Router using isolated Domain Services, Repository pattern with Mongoose/MongoDB, and strict DTO validation via Zod schemas. This leverages existing infrastructure while enabling future extraction.
6. What REST API architecture is recommended? A versioned /api/v1/... RESTful structure with standardized JSON response envelopes ({ success, message, data, meta }), HTTP status codes, bearer JWT sessions, cursor/offset pagination, and centralized error logging.
7. What authentication options should be considered? MVP: Email/Password + Phone Number with 6-digit SMS OTP + Google OAuth.
Post-MVP: Facebook Login, passwordless magic links, and session termination across all active devices.
8. How should Bangla + English work? Routing via next-intl (/bn/..., /en/...) with cookie fallback; static UI translated via JSON catalogs; course/lesson content stored in bilingual database fields; typography powered by Google Fonts Hind Siliguri and Plus Jakarta Sans.

Operational: Uncontrolled video streaming egress costs without CDN tokens.

Small Team (3 Devs + 1 QA): 10–13 calendar weeks (approx. 50–65 working days).
11. What is the recommended order of development? 1. Security & Auth Stabilization → 2. Role-Based Access Control (RBAC) → 3. Course Hierarchy & Media Hosting → 4. Learning Portal & Progress → 5. Exam/Quiz Engine → 6. Payments & Enrollments → 7. Multilingual → 8. QA Launch Gate.
12. What should I do immediately after this research? Immediately close the plaintext password vulnerability in /api/register, fix the form input binding bug in Register.tsx, standardize MongoDB schemas, and implement the formal /api/v1/auth service.

01 Executive Summary

TechSprout School is poised to become a premiere online learning management system (LMS) purpose-built for the Bangladeshi ecosystem and regional international learners. The platform aims to bridge the critical gap between academic instruction, practical technical skills, and structured career readiness. To achieve market leadership, TechSprout must deliver a flawless, high-retention digital learning experience characterized by robust video delivery, interactive online examinations, instant academic evaluation, and frictionless localized payments.

This document presents the findings of an exhaustive architectural, codebase, security, and product audit of the current TechSprout repository. While the codebase exhibits modern visual aesthetics using Next.js 16, Tailwind CSS v4, and Radix UI primitives, it is currently in a pre-alpha prototype state. The existing implementation lacks core functional backends, exposes serious security vulnerabilities, and utilizes static mock data across all public catalogs.

Strategic Assessment

TechSprout School currently possesses a polished storefront, but zero operational LMS engines. Launching the platform requires transitioning from static marketing mockups into an enterprise-grade modular monolith with true data persistence, secure multi-role authentication, automated grading, and compliant MFS billing.

07 Authentication & Identity Management Strategy

A critical comparative benchmark between modern e-commerce/LMS authentication (phone OTP + social login) and TechSprout's current state reveals vital strategic requirements for the Bangladeshi market:

Authentication Feature Classification

Authentication Method Classification Architectural & Market Rationale Security Controls
Email + Strong Password Required (MVP) Essential for instructors, corporate learners, and administrative personnel who manage formal credentials. Argon2id hashing, min 8 chars, 1 uppercase, 1 symbol. Zod validation.
Phone Number + 6-Digit OTP Required (MVP) The primary login standard in Bangladesh. Most students use smartphones and lack active email habits. Redis rate limiting (max 3 OTP requests / 15 mins), 3-minute TTL, constant-time compare.
Google OAuth 2.0 Required (MVP) One-tap sign-in reduces friction on desktop browsers and Android smartphones dramatically. PKCE verification, strict redirect URI validation, automatic email linking.
Facebook Login Recommended Widely utilized in Bangladesh, but frequent API policy shifts and Meta developer review delays make it risky for initial MVP launch. Strict state token validation to prevent CSRF authentication hijack.
Password Reset via SMS/Email Required (MVP) Without automated password resets, support teams will be overwhelmed with locked account tickets. Signed, single-use, cryptographically random token with 15-minute expiration.
Session Management & Invalidation Required (MVP) NextAuth JWT with HttpOnly cookies. Support revoking tokens upon role change or password reset. HttpOnly, Secure, SameSite=Lax cookie flags; token rotation.
Logout from All Devices Recommended Prevents credential sharing where multiple students pool money to access a single paid account. User tokenVersion integer incremented on global logout.
Brute-Force & Abuse Protection Required (MVP) Prevents SMS gateway drainage (financial loss) and credential stuffing attacks. Upstash Redis sliding-window rate limiting per IP and per phone number.

08 Language & Internationalization Strategy

To serve Bangladeshi students while maintaining institutional rigor, TechSprout School must support both বাংলা (Bangla) and English as first-class languages. The architecture must avoid hardcoded string conditionals and establish an extensible i18n foundation:

1. Routing & Locale Persistence Architecture

  • Subpath Routing: Utilize Next.js 16 with next-intl to support canonical localized paths:
    techsprout.edu/bn/courses (Bangla) and techsprout.edu/en/courses (English).
  • Default Locale: Default to bn for visitors originating from Bangladesh IP addresses (detected via Cloudflare CF-IPCountry header), with cookie fallback (NEXT_LOCALE=bn).
  • Language Switcher: An accessible language toggle in the primary navigation header and mobile drawer, persisting user choice across sessions.

2. Content Translation Strategy

[ Content Layer Separation ] | +---------------------------+---------------------------+ | | [ Static UI Chrome ] [ Dynamic Dynamic LMS Content ] • Navigation, buttons, labels • Course titles, descriptions • Validation & error messages • Lessons, syllabus, exam questions • Handled via JSON Dictionaries • Stored as localized database subdocuments messages/bn.json, messages/en.json { title: { bn: "...", en: "..." } }

3. Typography, Number & Currency Formatting

  • Bangla Typography: Google Font Hind Siliguri or Noto Sans Bengali loaded via next/font/google with appropriate font-display swap to eliminate FOIT (Flash of Invisible Text).
  • Numeral Localization: A centralized utility function converting western digits to Bengali numerals in Bangla mode (e.g., 15 → ১৫).
  • Currency Standards: Display course pricing in Bangladeshi Taka (৳ ১,৫০০) for local currency and USD ($ 20.00) for international visitors.
  • Date & Time: Formatting dates using native Intl.DateTimeFormat('bn-BD', { ... }) for natural Bengali calendar displays.

09 Backend Engineering & Services Plan

The backend of TechSprout School will be structured as a Clean Modular Monolith built directly on Next.js 16 App Router Route Handlers. This provides serverless scalability, low latency, and zero deployment friction while strictly isolating business domains:

[ Client Application / Web UI ] <---( HTTPS JSON )---> [ REST API Route Handlers (/api/v1/...) ] | +-----------+-----------+ | | [ Zod DTO Validation ] [ JWT Auth & RBAC Guard ] | | +-----------+-----------+ | [ Domain Service Layer ] (Auth, Course, Progress, Exam, Payment) | +-----------+-----------+ | | [ Mongoose Repository ] [ External Cloud Integrations ] | • Cloudflare Stream / Bunny.net [ MongoDB Atlas Cluster ] • SSLCommerz / bKash Gateway (Replica Sets, Indexes) • SMS Gateway (SSL Wireless) • Email Dispatch (Resend/SES)

Core Backend Architectural Pillars

  • Standardized API Response Envelopes: All endpoints return a uniform envelope ensuring client predictability:

{
  "success": true,
  "message": "Operation completed successfully",
  "data": { ... },
  "meta": { "page": 1, "limit": 20, "total": 142, "totalPages": 8 }

// Error Response (HTTP 400/401/403/404/422/500)
{
  "success": false,
  "message": "Validation failed for one or more fields",
  "errorCode": "VALIDATION_ERROR",
  "errors": [{ "field": "email", "message": "Invalid email address format" }]

  • Database Transactions: Atomic multi-document transactions (via mongoose.startSession()) for checkout, enrollment, and exam submission to prevent data corruption during network drops.
  • Media Storage Pipeline: Direct client-to-cloud uploads using presigned S3/Cloudflare R2 URLs for avatars, lecture PDFs, and assignment files. Video lectures ingested through Bunny.net Stream or Cloudflare Stream with automatic HLS transcode.
  • Background Jobs: Lightweight asynchronous processing using Upstash QStash or BullMQ for sending enrollment emails, SMS OTP alerts, and certificate PDF generation.

12 Online Examination & Assessment Engine

The online examination engine delivers rigorous, tamper-resistant academic testing. It supports formative quizzes (end-of-lesson knowledge checks) and summative final exams (required for course certificates):

1. Question Formats & Randomization

  • Single-Choice MCQ: Traditional question with 4 options and exactly one correct answer.
  • Multiple-Answer MCQ: Questions with multiple correct options (partial credit logic applied).
  • True / False: Rapid conceptual verification questions.
  • Question Pool Randomization: If an exam requires 20 questions, the server draws randomly from an instructor-curated pool of 50 questions, ensuring adjacent students receive different tests.
  • Option Shuffling: The order of options (A, B, C, D) is cryptographically shuffled for each attempt.

2. Examination Lifecycle & Integrity Controls

[ Student Clicks Start Exam ] | v [ Server Generates Attempt Record ] → Records startedAt timestamp; Computes hardDeadline = startedAt + duration | v [ Client Displays Questions ] → Client timer countdown (synced with server via Heartbeat) | +-------------+-------------+ | | v v [ Normal Submission ] [ Hard Timeout Triggered ] → Server worker automatically auto-submits attempt upon hardDeadline | | +-------------+-------------+ | v [ Server Evaluation Worker ] → Matches answers against answer keys; Applies negative marking if enabled; Creates Result

3. Anti-Cheating & Proctoring Mechanisms (MVP vs. Post-MVP)

  • Full-Screen Lock & Blur Detection (MVP): Browser window.onblur events trigger warning dialogs. Exceeding 3 blur events auto-submits the exam with an academic integrity infraction flag.
  • Copy-Paste & Context Menu Disable (MVP): CSS and JavaScript restrictions preventing learners from copying question text to search engines.
  • IP / Multiple Device Lock (MVP): An active exam attempt locks the user session; concurrent logins from another IP address are blocked until the exam completes.
  • Webcam AI Proctoring (Future v2+): Facial detection, tab monitoring, and periodic snapshots deferred until post-MVP.

13 Evaluation, Grading & Academic Results System

The evaluation system determines learner competency and dictates certificate eligibility. It combines automated computation with instructor moderation:

Grading Algorithms & Negative Marking

  • Instant Scoring: For objective questions (MCQ, True/False), evaluation executes in under 200ms upon submission. Correct options yield positive points; incorrect choices apply negative marking if designated by the instructor (e.g., -0.25 marks per error to penalize guessing).
  • Passing Score Thresholds: Courses enforce a configurable passing percentage (default 70%). Students falling below threshold receive actionable breakdown feedback and must observe a 24-hour retake cooldown period.
  • Grading Curves & Letter Grades: A+ (80-100%), A (70-79%), B (60-69%), C (50-59%), F (<50%).

Certificate Issuance Pipeline

Upon achieving ≥70% on the final course exam AND 100% lesson watch completion, the system automatically dispatches an asynchronous job to generate an accredited completion certificate. The PDF features a cryptographically generated SHA-256 hash, student full name, instructor signature, completion date, and an interactive QR code linking to techsprout.edu/verify/:certificateId.

15 Security Requirements & Threat Mitigation

An enterprise LMS processes sensitive personal identifiable information (PII), proprietary curriculum intellectual property, and financial transactions. Below is the security audit and OWASP Top 10 mitigation framework:

Critical Vulnerabilities Detected in Current TechSprout Repository
  • Plaintext Passwords (CWE-312): In src/app/api/(user)/register/route.ts, User.create({ ...bodyData }) persists passwords directly to MongoDB without cryptographic hashing. Remediation: Hash passwords using Argon2id with 64MB memory cost prior to insert.
  • Mass Assignment & Role Escalation (CWE-915): The register endpoint accepts unchecked JSON objects. A malicious request specifying { "role": "admin" } immediately gains superuser privileges. Remediation: Explicit DTO sanitization via Zod schemas, hardcoding new registrations to role: 'student'.
  • Missing Route Guarding (CWE-285): src/middleware.ts is an empty stub. Admin dashboards and internal user data are vulnerable to unauthenticated scraping. Remediation: Implement NextAuth middleware enforcing valid JWT sessions and role matching.
  • Unbounded SMS / OTP Abuse (CWE-307): The OTP mechanism lacks sliding-window rate limiting. Attackers could spam requests, depleting platform SMS gateway funds. Remediation: Redis rate limiter restricting requests to 3 per phone number per 15 minutes.

OWASP Top 10 LMS Hardening Guidelines

OWASP Threat Category LMS Attack Vector Architectural Countermeasure
A01: Broken Access Control Student modifies lesson ID in URL to view unpurchased lectures. Server-side enrollment verification before returning video streaming tokens.
A02: Cryptographic Failures Cleartext credentials intercepted in transit. Enforce TLS 1.3, HSTS headers, and Argon2id password hashing with distinct per-user salts.
A03: Injection NoSQL query injection via malicious MongoDB operators ($gt, $or). Strict Zod schema validation; Mongoose parameterized models; sanitize user input.
A04: Insecure Design Exam answers sent in client payload and inspected via DevTools. Answer keys NEVER sent to client. Evaluation performed strictly on server upon submission.
A05: Security Misconfiguration Exposing stack traces or database connection URIs in error responses. Sanitize production API errors via errorResponse(); disable verbose Next.js error overlays.
A07: Identification & Auth Failures Brute-forcing 6-digit OTP codes or passwords. Maximum 5 incorrect attempts before invalidating OTP and locking account for 30 minutes.
A08: Software & Data Integrity Tampered payment webhook payloads granting free course access. HMAC-SHA256 signature verification on all SSLCommerz and bKash IPN webhooks.

Architectural Rules for Mobile Readiness

  • Stateless REST Contracts: All /api/v1/ endpoints must support Authorization Bearer headers in addition to browser cookies, enabling native mobile apps to authenticate without session workarounds.

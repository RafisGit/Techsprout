## 1. Executive Summary & Benchmark Verdict

Pursuant to the conditional senior architectural authorization in [`P7.0_SENIOR_DECISION_RECORD.md`](file:///d:/Work/2026/techsprout-main/docs/research/p7.0/P7.0_SENIOR_DECISION_RECORD.md) and [`ADR-P7-001`](file:///d:/Work/2026/techsprout-main/docs/architecture/adr/ADR-P7-001-learning-telemetry-privacy-and-fts.md), this report establishes the **measured empirical baseline** for native PostgreSQL Full-Text Search (`tsvector` with a GIN index) across a representative educational corpus (11 courses, 100 lessons, ~37,000 words, 302,978 characters) on an isolated, resource-constrained PostgreSQL instance mirroring Render Free tier database boundaries.

### High-Level Benchmark Verdict:

```text
========================================================================================
BENCHMARK VERDICT: 
  - LATENCY TARGET (p95 < 50 ms):              PASSED (p95 = 0.51 ms - 0.66 ms)
  - RESOURCE & HEADROOM GATE (>= 30% Headroom): PASSED (> 70% RAM Headroom, ~1MB Total)
  - RELEVANCE TARGET NDCG@5 (>= 0.80):          FAILED (Measured: 0.5100 Overall)
  - RELEVANCE TARGET RECALL@5 (>= 0.85):        FAILED (Measured: 0.2328 Overall)
  - ZERO-RESULT QUERIES (Target: 0):            FAILED (10 / 32 Queries Returned 0)
OVERALL OUTCOME: FTS FAILS APPROVED RELEVANCE BASELINE — PGVECTOR EVALUATION GATED
========================================================================================
```

Native PostgreSQL Full-Text Search demonstrates **exceptional latency** (sub-millisecond $p95$ up to 10 concurrent clients, over 14,000 queries/second throughput) and an **extremely compact footprint** (~1MB total database relation size, fitting comfortably within 64MB shared buffers on the 256MB free-tier RAM ceiling). 

However, native FTS **fails the approved relevance baseline**:
1. **Zero Typo Tolerance:** Standard English dictionary stemming cannot match misspellings (e.g., `dokker`, `typsecript`, `drizle`), resulting in $0.0000$ NDCG and $0.0000$ Recall across all 8 noisy queries.
2. **Conjunctive Query Brittleness:** In multi-word natural queries, `websearch_to_tsquery` requires all terms to be present, dropping queries where conversational filler words are absent from the document.
3. Even on clean technical queries, NDCG@5 is **0.6800** (below the 0.80 threshold) and Recall@5 is **0.3104** (below the 0.85 threshold) due to term-frequency limitations across related lessons.

### 3.2 Database Schema & Weighted GIN Index Configuration
Temporary benchmark table schema:
```sql
CREATE TABLE benchmark_lessons (
  id SERIAL PRIMARY KEY,
  course_id INT NOT NULL,
  course_title TEXT NOT NULL,
  module_title TEXT NOT NULL,
  lesson_id INT NOT NULL,
  lesson_title TEXT NOT NULL,
  lesson_content TEXT NOT NULL,
  keywords TEXT[] NOT NULL,
  search_vector tsvector
);
```

Search vectors were generated using the standard PostgreSQL `english` dictionary (Snowball stemmer) with weight hierarchies:
```sql
UPDATE benchmark_lessons
SET search_vector = 
    setweight(to_tsvector('english', coalesce(course_title, '')), 'A') ||
    setweight(to_tsvector('english', coalesce(module_title, '')), 'B') ||
    setweight(to_tsvector('english', coalesce(lesson_title, '')), 'A') ||
    setweight(to_tsvector('english', coalesce(lesson_content, '')), 'C');

CREATE INDEX benchmark_lessons_search_idx ON benchmark_lessons USING gin(search_vector);
```

### 3.3 Query Execution Pattern
Queries were executed using PostgreSQL's recommended web search parser with positional ranking:
```sql
SELECT lesson_id, course_title, lesson_title,
       ts_rank_cd(search_vector, websearch_to_tsquery('english', $1)) AS rank
FROM benchmark_lessons
WHERE search_vector @@ websearch_to_tsquery('english', $1)
ORDER BY rank DESC
LIMIT 5;
```

### 3.4 Ground-Truth Relevance Labeling & Metrics
32 synthetic test queries were authored across four distinct categories. Ground-truth relevance was independently assigned on a 4-point graded scale:
- **Grade 3 (Perfect Match):** The exact lesson specifically designed to teach the queried concept.
- **Grade 2 (Highly Relevant):** Sibling lessons in the same module covering direct prerequisites or direct applications.
- **Grade 1 (Partially Relevant):** Lessons in related modules mentioning the concept in context.
- **Grade 0 (Irrelevant):** All other lessons in the corpus.

Metrics measured:
- **NDCG@5 (Normalized Discounted Cumulative Gain at rank 5):**
  $$\text{DCG@5} = \sum_{i=1}^5 \frac{2^{rel_i} - 1}{\log_2(i + 1)}, \quad \text{NDCG@5} = \frac{\text{DCG@5}}{\text{IDCG@5}}$$
- **Recall@5:**
  $$\text{Recall@5} = \frac{\text{Relevant lessons retrieved in top 5 } (rel \ge 1)}{\text{Total relevant lessons in ground truth } (rel \ge 1)}$$
- **Zero-Result Count:** Queries returning exactly 0 rows.

### 4.3 Analysis of Relevance Failures
1. **Misspellings & Slang (Category 3 — 100% Failure Rate):**  
   PostgreSQL's standard `english` dictionary parses lexemes via strict character matching followed by Snowball suffix stripping (`multistage` $\rightarrow$ `multistag`). It has zero phonetic or Levenshtein distance matching. Queries containing typos like `dokker`, `typsecript`, or `drizle` produced **zero search vector matches**.
2. **Conjunctive Matching Drops (Category 2 — 25% Zero-Result Rate):**  
   `websearch_to_tsquery` treats unquoted terms as a boolean `AND` conjunction ($t_1 \ \& \ t_2 \ \& \ \dots \ \& \ t_n$). In Q10 (`best practices for error handling in asynchronous Node.js`), while lesson 26 covers asynchronous error handling and lesson 30 covers validation filters, no single lesson contained all 8 stemmed terms simultaneously, causing the query to return 0 rows.
3. **Low Recall Across Related Lessons:**  
   In technical curriculums, related concepts are distributed across multiple lessons (e.g., Docker layers, container security, Alpine images). Because FTS does not perform semantic expansion, it retrieves only the single lesson containing the exact keywords, yielding an average Recall@5 of only **0.2328** (target: $\ge 0.85$).

## 8. Root Cause Analysis & Technical Recommendations

### 8.1 Why Native FTS Failed the Relevance Baseline
1. **Lack of Fuzzy / Phonetic Matching:** In an educational platform, students frequently search with approximate spellings (`dokker`, `typsecript`, `sslcommerz paymnt`). Native FTS dictionary stemming cannot bridge this gap, causing instant 0-result dropouts.
2. **Boolean Conjunction Penalty:** `websearch_to_tsquery` translates natural user questions into `AND` boolean queries. If a student includes extraneous conversational terms that do not appear verbatim in the lesson text, the query returns 0 results despite the lesson being an exact match for the core technical concept.
3. **Absence of Semantic Generalization:** Native FTS treats words as independent symbols. A lesson explaining "container layer caching" is not recognized as relevant to "Docker image optimization" unless those exact stems co-occur.

### 8.2 Recommended Architectural Pathways Before Considering `pgvector`

Before escalating to heavyweight vector embeddings (`pgvector`), senior leadership should evaluate two lightweight PostgreSQL optimizations that preserve the free-tier memory ceiling:

#### Option A: PostgreSQL Trigram Extension (`pg_trgm`) Hybrid Fallback
- **Mechanism:** Enable PostgreSQL's native `pg_trgm` extension. If `websearch_to_tsquery` returns 0 rows (or low rank), execute a secondary fallback query using trigram similarity (`similarity(lesson_title, query) > 0.3`).
- **Memory Impact:** Trigram GIN indexes on lesson titles and keywords add an estimated ~200kB of index storage, easily fitting within the 256MB RAM limit.
- **Expected Impact:** Completely resolves the 8/8 misspelling failures and significantly elevates NDCG@5.

#### Option B: Application-Layer Query Relaxation & Disjunction
- **Mechanism:** If a strict conjunctive query returns 0 rows, the NestJS query builder strips stop-words and constructs a disjunctive query with term weighting:
  $$\text{to\_tsquery}('english', t_1 \mid t_2 \mid \dots \mid t_n)$$
  ordered by `ts_rank_cd`.
- **Expected Impact:** Resolves the multi-word question dropouts (e.g., Q10, Q16) without database schema modifications.

#### Option C: `pgvector` Evaluation Gate Assessment
- **Status under ADR-P7-001:** Because native FTS failed the agreed relevance criteria, evaluating `pgvector` is **conditionally eligible** for discussion.
- **Constraints:** Under [`ADR-P7-001`](file:///d:/Work/2026/techsprout-main/docs/architecture/adr/ADR-P7-001-learning-telemetry-privacy-and-fts.md), `pgvector` remains gated on evidence that its HNSW/IVFFlat index build and query memory fit within the 256MB RAM ceiling with **at least 30% verified memory headroom**.
- **Governance Mandate:** **`pgvector` is NOT authorized by this benchmark.** No extension installation, embedding generation, or infrastructure upgrades may proceed without formal senior architectural review of these findings.

## 2. Selected Telemetry Privacy Approach

Senior leadership has reviewed the architectural trade-offs between historical data utility and student data protection. **Exactly one approach is selected and approved:**

- [x] **Selected & Approved:** **Anonymized/Hashed Telemetry with Local-First Aggregation, PII Stripping at Ingestion**  
  *Rationale:* Formally recorded in [`ADR-P7-001`](file:///d:/Work/2026/techsprout-main/docs/architecture/adr/ADR-P7-001-learning-telemetry-privacy-and-fts.md). Raw search queries and raw request payloads are never persisted. Ingestion enforces strict allowlisting and strips all PII at the boundary. User and session identifiers are transformed with a daily rotating salt hash ($\text{HMAC-SHA256}$) held purely in memory. The kill switch `TELEMETRY_ENABLED=false` provides operational emergency shutdown.
- [ ] *Superseded / Rejected:* Hard Deletion via `ON DELETE CASCADE` (rejected due to destructive mutation of aggregate drop-off analytics).
- [ ] *Superseded / Rejected:* Nullable Foreign Key via `ON DELETE SET NULL` (rejected as a standalone privacy solution because nullifying `user_id` does not scrub payload PII or auxiliary proxy access logs).

## 4. Conditional Authorization Criteria

Phase 7.1 implementation and eventual production release are subject to strict, verified compliance with the following two sets of criteria:

### 4.1 Pre-Implementation Conditions (Gating Phase 7.1 Kickoff)
1. **Canonical ADR Formalized:** [`ADR-P7-001`](file:///d:/Work/2026/techsprout-main/docs/architecture/adr/ADR-P7-001-learning-telemetry-privacy-and-fts.md) recorded and cross-linked directly from the scope-change document and phase specifications.
2. **Scope Change Request Formalized:** [`SCR-P7-01`](file:///d:/Work/2026/techsprout-main/docs/research/p7.0/SCR-P7-01_SCOPE_CHANGE_REQUEST.md) recorded and linked directly to the ADR.
3. **FTS Benchmark Acceptance Criteria Documented:** Explicit pass/fail latency ($p95 < 50\text{ms}$) and relevance thresholds ($\text{NDCG@5} \ge 0.80$, $\text{Recall@5} \ge 0.85$) defined across a reproducible 30-query test set.
4. **Documented Free-Tier Resource Limits & Memory Gate:** Evidence-backed baseline of Render Free tier limits (512MB RAM container, 25MB Redis limit) recorded, with the 30% RAM headroom gate defined before any `pgvector` consideration.

### 4.2 Pre-Production Release Conditions (Gating Phase 7.1 Release Gate Sign-off)
1. **Automated CI Privacy & Sanitization Tests:** Monorepo test suites must include automated integration tests asserting that raw search queries, email addresses, and unhashed identifiers are strictly absent from `learning_events` rows and analytics logs.
2. **Tested Down-Migration & Zero-Lock Rollback:** A verified down-migration script must accompany Migration 0009. Index removal and rollback procedures must be designed to avoid acquiring blocking locks on core transactional tables (`users`, `courses`, `lessons`).
3. **Simulated-Load Capacity Evidence:** Staging load benchmarks must verify that batch telemetry writes stay strictly within database connection-pool ceilings, memory limits, and disk growth budgets without triggering worker container restarts or Redis evictions.
4. **Release Governance Review:** Privacy, data retention (90-day checkpoint pruning), and erasure safeguards must be formally audited and signed off in the staging release gate report.

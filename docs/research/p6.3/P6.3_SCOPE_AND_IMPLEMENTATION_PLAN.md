- `apps/api/src/test/test-helper.ts`

#### Dependencies & Prerequisites:
- Completion of P6.3 Scope Freeze.

#### Acceptance Criteria:
- `pnpm --filter @techsprout/contracts build` compiles cleanly with zero TypeScript errors.
- Migration `0008` executes forward and rollback cleanly against PostgreSQL 16.
- In-memory test suite runs cleanly.

#### Complexity & Risk:
- **Complexity:** Low.
- **Risk:** Low. Migration introduces secondary composite indexes using ordinary transactional DDL within Drizzle's migration runner. Standard PostgreSQL `CREATE INDEX` permits concurrent reads but acquires a `SHARE` lock that blocks writes (`INSERT`, `UPDATE`, `DELETE`) until the transaction completes. `CREATE INDEX CONCURRENTLY` cannot run inside a transaction block (PostgreSQL Error `25001`) and would require a separately verified non-transactional runner. Anticipated impact depends on table size, database load, and storage performance; because table volumes remain modest, using the existing transactional runner during standard deployment windows is recommended.

#### Range Estimate:
- **1.5 – 2.5 Engineering Days** (Assumes shared contract review and schema verification).

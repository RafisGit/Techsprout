### 2.1 Video Playback and Lesson Progress Tracking

- **Classification:** **`VERIFIED`**
- **Inspected Files:**
  - Client Player: [`apps/web/src/components/learning/VideoPlayer.tsx`](file:///d:/Work/2026/techsprout-main/apps/web/src/components/learning/VideoPlayer.tsx#L1-L193)
  - Classroom Viewer: [`apps/web/src/components/learning/LessonViewer.tsx`](file:///d:/Work/2026/techsprout-main/apps/web/src/components/learning/LessonViewer.tsx)
  - Learning Service: [`apps/api/src/modules/learning/learning.service.ts`](file:///d:/Work/2026/techsprout-main/apps/api/src/modules/learning/learning.service.ts#L740-L840)
  - Learning Controller: [`apps/api/src/modules/learning/learning.controller.ts`](file:///d:/Work/2026/techsprout-main/apps/api/src/modules/learning/learning.controller.ts#L125-L145)
  - Schema: [`apps/api/src/database/schema/progress.ts`](file:///d:/Work/2026/techsprout-main/apps/api/src/database/schema/progress.ts#L20-L48)
- **Detailed Findings:**
  1. **Client Tracking Hook & Dispatch:**
     - `VideoPlayer.tsx` maintains playback state via `videoRef` and listens to `onTimeUpdate` (`handleTimeUpdate:L93-L104`).
     - Progress checkpoints are throttled client-side to $\ge 15$ seconds of delta between dispatches (`L101`).
     - Discrete user interactions trigger immediate checkpoints: `onPause` (`handlePause:L107`), `onSeeked` (`handleSeeked:L113`), and `onEnded` (`handleEnded:L119`).
     - Checkpoint payload is sent via `saveProgressCheckpoint(courseId, lessonId, roundedSeconds)` targeting `POST /api/v1/learn/courses/:id/lessons/:lessonId/progress`.
  2. **Completion Threshold Calculation:**
     - A video is marked completed when `watchPositionSeconds >= Math.floor(0.9 * lesson.durationSeconds)` (90% threshold per requirement `AC-PROG-04`, confirmed in [`learning.service.ts:L794-797`](file:///d:/Work/2026/techsprout-main/apps/api/src/modules/learning/learning.service.ts#L794-L797)).
     - When all lessons in an enrollment are completed, `calculateProgress` triggers automated enrollment completion and issues a certificate via `certificateService.issueCertificateIfEligible` (`learning.service.ts:L845-877`).
  3. **Architectural Gaps & Telemetry Limitations:**
     - **In-Place Relational Overwrite:** The backend performs an `onConflictDoUpdate` on `lesson_progress.watch_position_seconds` ([`learning.service.ts:L806-826`](file:///d:/Work/2026/techsprout-main/apps/api/src/modules/learning/learning.service.ts#L806-L826)). Only the latest position snapshot is stored.
     - **Zero Event History:** No time-series log exists. Student pauses, seek trajectories (e.g. rewinding from 5:00 to 2:30), playback speeds, device metadata, or drop-off moments are discarded.
     - **Tab Exit Vulnerability:** `VideoPlayer.tsx:L131-L140` attempts an unmount cleanup `saveProgressCheckpoint` using a standard `Promise`. When a user closes the browser tab or navigates abruptly, browser processes frequently cancel asynchronous fetches, losing the exit point. There is zero implementation of `navigator.sendBeacon()` or `fetch(..., { keepalive: true })`.
     - **Absence of Telemetry Schema:** The `learning_events` table is **strictly absent** from the database (verified across migrations 0000–0008).

### 2.2 Domain-Event and Transactional-Outbox Architecture

- **Classification:** **`VERIFIED`**
- **Inspected Files:**
  - Outbox Service: [`apps/api/src/modules/events/outbox.service.ts`](file:///d:/Work/2026/techsprout-main/apps/api/src/modules/events/outbox.service.ts#L1-L91)
  - Domain Event Interface: [`apps/api/src/modules/events/domain-event.interface.ts`](file:///d:/Work/2026/techsprout-main/apps/api/src/modules/events/domain-event.interface.ts#L1-L30)
  - Outbox Schema: [`apps/api/src/database/schema/notifications.ts`](file:///d:/Work/2026/techsprout-main/apps/api/src/database/schema/notifications.ts#L104-L124)
- **Detailed Findings:**
  1. **Transactional Outbox Table:**
     - Defined as `outbox_events` in `notifications.ts`: columns include `id (UUID)`, `event_id (VARCHAR(100) UNIQUE)`, `event_type (VARCHAR(100))`, `actor_id (UUID)`, `entity_id (VARCHAR(100))`, `entity_type (VARCHAR(50))`, `payload (TEXT)`, `status (outbox_status: 'PENDING' | 'PUBLISHED' | 'FAILED')`, `retry_count (INTEGER)`, `last_error (TEXT)`, `published_at (TIMESTAMPTZ)`, and `created_at (TIMESTAMPTZ)`.
     - Indexed on `(status, created_at)` and unique on `event_id`.
  2. **Event Dispatch Mechanism:**
     - `OutboxService.emit(options)`:
       1. Inserts the event record into `outbox_events` with status `'PENDING'` (`L48-56`).
       2. Asynchronously enqueues a job into BullMQ via `notificationQueueService.enqueueNotificationJob` (`L64`).
       3. Updates the outbox row to `'PUBLISHED'` with timestamp `publishedAt` (`L68-73`).
       4. On queue failure, updates status to `'FAILED'` and increments `retry_count` (`L78-85`).
  3. **Registered Domain Event Types:**
     - 17 strongly-typed events defined in `domain-event.interface.ts:L1-17`:
       `OrderPlaced`, `OrderPaid`, `RefundRequested`, `RefundApproved`, `RefundRejected`, `RefundSettled`, `EnrollmentCreated`, `EnrollmentCancelled`, `CourseSubmittedForReview`, `CourseApproved`, `CourseReviewApproved`, `CourseRejected`, `CourseReviewRejected`, `LessonCompleted`, `QuizPassed`, `CertificateIssued`.
  4. **Architectural Evaluation for Telemetry:**
     - **Incompatible with High-Frequency Telemetry:** Writing every video heartbeat (e.g., every 60s across hundreds of active learners) to `outbox_events` and executing sequential relational row updates (`INSERT` $\rightarrow$ `UPDATE`) would severely degrade PostgreSQL write throughput and induce lock contention.
     - Telemetry events must bypass the transactional outbox and use either direct partitioned append-only ingestion or a dedicated Redis stream / BullMQ micro-batch buffer.

  - Render Production Blueprint: [`render.yaml`](file:///d:/Work/2026/techsprout-main/render.yaml#L41-L47)

- **Detailed Findings:**
  1. **BullMQ Queues Active:**
     - `techsprout-queue` managed in `QueueService`: default job options specify `attempts: 3`, exponential backoff (`delay: 1000`), `removeOnComplete: true`, and `removeOnFail: false` (dead-letter retention).
     - `techsprout-notifications` managed in `NotificationQueueService`: concurrency 5, processes asynchronous domain events and in-app/email dispatches.

     - The codebase does not share a unified Redis connection pool. Three separate `ioredis` instances are instantiated independently:

       2. `NotificationQueueService` (`apps/api/src/modules/notifications/notification-queue.service.ts:L33`)

  3. **Cloud Infrastructure Constraints:**
     - On Render Free Key-Value (Redis): memory limit is **25 MB**, policy is `maxmemoryPolicy: noeviction`, and external IP access is completely blocked (`ipAllowList: []`).
     - Buffering high-volume telemetry without strict memory caps or immediate drain workers risks fatal Redis OOM (`OOM command not allowed when used memory > 'maxmemory'`).

### 2.4 PostgreSQL Schema and Migration Conventions

- **Classification:** **`VERIFIED`**
- **Inspected Files:**
  - Migration Runner: [`apps/api/src/database/migrate.ts`](file:///d:/Work/2026/techsprout-main/apps/api/src/database/migrate.ts#L1-L36)
  - Migration Journal: [`apps/api/src/database/migrations/meta/_journal.json`](file:///d:/Work/2026/techsprout-main/apps/api/src/database/migrations/meta/_journal.json#L1-L69)
  - Latest Migration: [`apps/api/src/database/migrations/0008_analytics_foundation.sql`](file:///d:/Work/2026/techsprout-main/apps/api/src/database/migrations/0008_analytics_foundation.sql)
  - Schema Registry: [`apps/api/src/database/schema/index.ts`](file:///d:/Work/2026/techsprout-main/apps/api/src/database/schema/index.ts)
- **Detailed Findings:**
  1. **ORM & Driver Stack:**
     - Drizzle ORM (`drizzle-orm: ^0.39.3`) with `pg` (`^8.13.3`) connection pooling.
     - Schemas reside modularly in `apps/api/src/database/schema/*.ts` (25 schema files).
     - Standard conventions: `uuid('id').defaultRandom().primaryKey()`, PostgreSQL native enums via `pgEnum()`, UTC timestamps via `timestamp('...', { withTimezone: true }).defaultNow()`, and explicit foreign key cascading (`onDelete: 'cascade'`, `'set null'`, or `'restrict'`).
  2. **Migration History & Runner:**
     - Exactly 9 migrations are tracked in `_journal.json`:
       - `0000_initial_schema` (P1 foundation)
       - `0001_whole_living_tribunal`
       - `0002_small_talon` (learning progress & quizzes)
       - `0003_hard_night_thrasher`
       - `0004_payment_admin_subsystem` (P5.4 finance)
       - `0005_refund_requests_subsystem` (P5.4.5 refunds)
       - `0006_p6_1_notification_and_ownership` (P6.1 notifications & ownership)
       - `0007_instructor_platform_foundation` (P6.2 instructor portal)
       - `0008_analytics_foundation` (P6.3 composite indexes)
     - `apps/api/src/database/migrate.ts` executes `migrate(db, { migrationsFolder })`.
  3. **Critical Migration Constraint:**
     - Drizzle's Node-Postgres migrator wraps migration execution inside an atomic PostgreSQL transaction block (`BEGIN` ... `COMMIT`).
     - PostgreSQL explicitly forbids `CREATE INDEX CONCURRENTLY` inside transaction blocks (PostgreSQL Error `25001`).
     - Consequently, all indexes created via Drizzle run with standard `CREATE INDEX`, acquiring a `SHARE` lock that permits concurrent reads but temporarily blocks writes (`INSERT`, `UPDATE`, `DELETE`).

- **Detailed Findings:**
  1. **Authentication:**
     - Stateless JWT authentication via `JwtAuthGuard` and Passport JWT strategy. Access tokens validate user identity, account status (`ACTIVE`), and role assignment.
  2. **Role-Based Access Control (RBAC):**
     - Roles defined in `roles.ts`: `'admin'`, `'instructor'`, `'student'`.
     - `RolesGuard` enforces `@Roles(...)` metadata.
  3. **Zero-Trust Resource Ownership:**
     - `ResourceOwnershipGuard` enforces fine-grained authorization:
       - Admins bypass all ownership checks (`L59-61`).
       - Instructors must own the course to which any child entity belongs (`courses`, `modules`, `lessons`, `quizzes`, `quizQuestions`, `quizQuestionOptions`, `media`).
       - Ownership violations are logged to `audit_logs` (`L98-105`) and rejected with HTTP 403 Forbidden.
  4. **Rate Limiting:**
     - Global NestJS `@nestjs/throttler` (`^6.3.0`) registered in `app.module.ts:L40` with `ThrottlerGuard` bound as global APP_GUARD.
     - Sensitive routes override limits via `@Throttle({ default: { limit, ttl } })` (e.g. invoice downloads, CSV export, certificate issuance).

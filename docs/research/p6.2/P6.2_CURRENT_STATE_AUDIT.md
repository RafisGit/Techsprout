## 1. Executive Summary

This current-state audit inspects the TechSprout LMS repository to evaluate the existing codebase against the requirements of an institutional **Instructor Platform (Phase P6.2)**. 

### Key Findings:
1. **Strong Authorization Foundation:** Phases P1–P6.1 established a rigorous, zero-trust backend authorization architecture. The `ResourceOwnershipGuard` ([resource-ownership.guard.ts](file:///d:/Work/2026/techsprout-main/apps/api/src/common/guards/resource-ownership.guard.ts)) protects courses, modules, lessons, quizzes, questions, options, and media.
2. **Missing Instructor Experience:** While backend course management endpoints permit `@Roles('admin', 'instructor')`, the frontend currently has **zero dedicated `/instructor` routes**, no instructor dashboard, and no navigation links in the header for instructors.
3. **Information Architecture Defect:** When instructors navigate to `/admin/courses` (the only course management UI currently available), the top navigation `AdminNav` contains an "Overview" link to `/dashboard/admin/overview`. That page strictly checks `user.role === 'admin'` and throws a **403 Forbidden Access Denied** error to instructors.
4. **Broken Publishing Workflow:** The course publishing UI ([PublishingActions.tsx](file:///d:/Work/2026/techsprout-main/apps/web/src/components/admin/PublishingActions.tsx#L173-L176)) displays a static text notice instructing educators: *"When your curriculum is finalized, request administrative review for publication."* However, there is no button, no review queue endpoint, and no database status representing review (`course_status` enum only contains `DRAFT`, `PUBLISHED`, `ARCHIVED`).
5. **Dormant Learner Roster Endpoint:** A complete, secure course enrollment roster endpoint exists on the backend (`GET /api/v1/admin/courses/:id/enrollments`), enforcing course ownership checks. However, the frontend has **zero UI or API client integration** to allow instructors to view their students.

## 3. Detailed Breakdown of Discovered Defects & Architectural Quirks

### Defect 1: Information Architecture Defect (`AdminNav` Overview 403 Leak)
- **Location:** [AdminNav.tsx](file:///d:/Work/2026/techsprout-main/apps/web/src/components/admin/AdminNav.tsx#L16-L21) and [page.tsx](file:///d:/Work/2026/techsprout-main/apps/web/src/app/dashboard/admin/overview/page.tsx#L9-L16)
- **Mechanism:** In `AdminNav.tsx`, the "Overview" tab has `show: true` (visible to all users entering `/admin/*`, including instructors). The destination route `/dashboard/admin/overview` executes:
  ```typescript
  if (!user || user.role !== 'admin') {
    return (
      <div className='p-6 bg-red-50 text-red-700 rounded-lg border border-red-200'>
        <h2 className='text-xl font-bold'>Access Denied (403 Forbidden)</h2>
        <p className='mt-2'>You do not have administrative privileges to access this page.</p>
      </div>
    );
  }
  ```
- **User Impact:** When instructor Dr. Sarah Mitchell clicks "Overview" in the navigation bar, she is greeted with an alarming 403 Forbidden Access Denied banner.
- **Root Cause:** Mixing Administrator-only views with Instructor-accessible catalog management under a single navigation component without role gating.
- **Remediation in P6.2:** Create a dedicated, clean `/instructor/*` route tree with an `InstructorNav` component that never links to admin-only pages. In `AdminNav.tsx`, set `show: isAdmin` on the Overview tab or point instructors to `/instructor/dashboard`.

---

### Defect 2: Missing Instructor Navigation Entry Points
- **Location:** [Header.tsx](file:///d:/Work/2026/techsprout-main/apps/web/src/components/header/Header.tsx#L202-L215)
- **Mechanism:** The top navigation bar in `apps/web` only renders links to `My Courses` and `Orders` for authenticated users. The mobile navigation drawer (`Sheet`) also only contains links to `My Courses` and `Orders`.
- **User Impact:** Instructors and Administrators who log in have **no UI entry point** to reach course management. They are forced to guess or manually bookmark `/admin/courses`.
- **Remediation in P6.2:** Add a role-aware navigation dropdown or portal button in `Header.tsx`:
  - If `user.role === 'instructor'`, render an "Instructor Portal" link pointing to `/instructor/dashboard`.
  - If `user.role === 'admin'`, render an "Admin Portal" link pointing to `/dashboard/admin/overview`.

### Defect 3: Dead Static Notice for Course Publishing Review
- **Location:** [PublishingActions.tsx](file:///d:/Work/2026/techsprout-main/apps/web/src/components/admin/PublishingActions.tsx#L172-L176)
- **Mechanism:** Lines 172–176 render:
  ```tsx
  <div className='p-3 bg-gray-50 border border-gray-200 rounded-lg text-xs text-gray-600'>
    <strong>Instructor Notice:</strong> Publishing, unpublishing, and archiving are restricted to institutional administrators. When your curriculum is finalized, request administrative review for publication.
  </div>
  ```
- **User Impact:** Instructors finish authoring modules, lessons, and quizzes, but have no way to "request administrative review". The text promises a workflow that does not exist in the code.
- **Root Cause:** Incomplete lifecycle specification between P2 catalog foundation and P6.2 instructor platform.
- **Remediation in P6.2:** Implement an explicit Course Review state machine:
  1. Add `IN_REVIEW` to `course_status` enum.
  2. Create a "Submit for Publication Review" button with a confirmation modal.
  3. Emit a `CourseSubmittedForReview` event to alert institutional admins.
  4. Provide an Admin Review Queue where administrators can review curriculum and either Approve (transitions course to `PUBLISHED`) or Reject (reverts to `DRAFT` with structured feedback notes).

### Defect 4: Roster Endpoint Exists on Backend But Unused on Frontend
- **Location:** [admin-enrollments.controller.ts](file:///d:/Work/2026/techsprout-main/apps/api/src/modules/enrollments/admin-enrollments.controller.ts#L81-L116) and [enrollments.service.ts](file:///d:/Work/2026/techsprout-main/apps/api/src/modules/enrollments/enrollments.service.ts#L794-L820)
- **Mechanism:** The backend endpoint `GET /api/v1/admin/courses/:id/enrollments` accepts `@Roles('admin', 'instructor')` and validates:
  ```typescript
  if (actor.role === 'instructor' && course.instructorId !== actor.id) {
    throw new ApiException('Access denied: you do not own this course', HttpStatus.FORBIDDEN, 'NOT_COURSE_OWNER');
  }
  ```
- **User Impact:** The backend is fully equipped to serve enrollment data to instructors, including student name, email, enrollment date, progress percentage, and status. However, the frontend has **no screen or component** to display this data.
- **Remediation in P6.2:** Create the `/instructor/courses/[id]/learners` page in Next.js, consume this endpoint, and render an interactive student roster with search, status filters, and progress tracking.

### Defect 5: Missing Instructor Profile Schema & Public Bio
- **Location:** [users.ts](file:///d:/Work/2026/techsprout-main/apps/api/src/database/schema/users.ts)
- **Mechanism:** The `users` table only records: `id`, `name`, `username`, `email`, `phone`, `passwordHash`, `isActive`, `isVerified`, timestamps.
- **User Impact:** When students browse the public catalog ([courses/[slug]](file:///d:/Work/2026/techsprout-main/apps/web/src/app/courses/[slug]/page.tsx)), courses list the instructor's name, but there is no biographical information, headline, academic credentials, or profile photo.
- **Remediation in P6.2:** Introduce an additive `instructor_profiles` table linked 1:1 with `users`. Add an Instructor Profile edit page (`/instructor/profile`) where educators can manage their professional summary, credentials, and social links.

## 4. Previously Reported P6.1 Limitations (Verification Status)

During the P6.1 live production release review, three operational boundaries were documented:
1. **Authenticated In-App Notification E2E Flow:** Notification database records and IDOR protection were verified, but an end-to-end interactive notification toast flow was not triggered in live production.
   - *Audit Status:* **Confirmed as non-blocking for P6.2**. The underlying engine (`notifications`, `outbox_events`, `BullMQ`) is fully operational and passes 32 backend test suites. P6.2 will cleanly leverage this engine for review request notifications.
2. **Live Email Delivery:** Staging and production use sandbox/mock configurations for Resend/SMTP to avoid spamming real addresses during automated audits.
   - *Audit Status:* **Preserved invariant**. P6.2 review notifications will emit in-app notifications primarily; email outbox events will remain safe in staging/development.
3. **Cloudinary Media Upload Restriction in Staging:** Staging infrastructure intentionally restricts arbitrary binary file uploads to preserve production quotas.
   - *Audit Status:* **Preserved invariant**. P6.2 instructor testing will continue to use mocked media responses and existing seeded media records (`storageKey: 'mock/seed-avatar'`).

## 5. Audit Conclusion

The TechSprout codebase is in an excellent, stable state (1,195 passing tests, clean git working tree, robust security guards). 

However, **there is currently no Instructor Platform UX**. The existing course authoring screens are bolted onto the `/admin` route tree, resulting in role confusion, navigation 403 errors, and a dead publishing loop.

P6.2 must resolve these gaps by delivering a dedicated, professional `/instructor/*` platform, an institutional Course Review workflow, and learner roster visibility, while preserving all existing security guards and financial invariants.

## 1. Executive Summary

This master review package delivers a comprehensive, evidence-based evaluation of the TechSprout LMS repository to define, architect, and schedule **Phase P6.2 (Instructor Platform)**. 

Every finding, gap analysis, and architectural proposal in this review has been verified against the actual repository source code, PostgreSQL database schemas, NestJS controllers, Next.js frontend routes, and automated test runners.

### Core Audit Takeaways:
1. **The System is Stable & Well-Guarded:** The platform is operating at a verified baseline of **1,195 passing automated tests** across 45 test files. Phases P1 through P6.1 have established an unyielding foundation for catalog management, student enrollment, checkout, quiz assessments, automated certificate issuance, and decoupled notification dispatch.
2. **The Security Foundation is Production-Grade:** The `ResourceOwnershipGuard` ([resource-ownership.guard.ts](file:///d:/Work/2026/techsprout-main/apps/api/src/common/guards/resource-ownership.guard.ts)) already provides bulletproof, database-verified horizontal privilege isolation across courses, modules, lessons, quizzes, questions, options, and media assets.
3. **The Instructor Frontend Experience is Completely Missing:** Despite having functional backend CRUD endpoints for course authoring, there is currently **no dedicated instructor user interface**. The frontend has **zero routes under `/instructor`**, no instructor dashboard, and no entry links in `Header.tsx`.
4. **Three Critical Gaps Require Immediate Resolution in P6.2:**
   - **403 Navigation Leak:** Instructors entering `/admin/courses` see an "Overview" tab in `AdminNav.tsx` that links to `/dashboard/admin/overview`, which immediately throws a **403 Forbidden Access Denied** error to instructors.
   - **Dead Static Publishing Workflow:** The course publishing UI ([PublishingActions.tsx](file:///d:/Work/2026/techsprout-main/apps/web/src/components/admin/PublishingActions.tsx#L173-L176)) displays a static text notice promising an administrative review workflow that does not exist in the database or backend.
   - **Unused Roster API:** A complete course enrollment roster endpoint exists on the backend (`GET /api/v1/admin/courses/:id/enrollments`), but the frontend has zero UI or API client integration to display enrolled students to educators.

This review defines an implementation-ready, 7-package plan to deliver a secure, institutional Instructor Platform in **44–60 engineer-hours (5.5–7.5 engineer-days)** with zero regressions.

## 2. Answers to the 12 Core Master Review Questions

### Q1: What is the current, verified state of the platform?
- **Git State:** Clean working tree on branch `main`, commit `d67d8eed0ed570e1e347e7952b9ae0cc80fbb38b`.
- **Test Baseline:** 1,195 tests passing (935 in `@techsprout/api`, 260 in `@techsprout/web`).
- **Infrastructure:** Dual-environment isolation verified. Production is active on Render API + Vercel Web. Staging is operating on separate, dedicated Render and Vercel instances.
- **P6.1 Verification:** Decoupled Notification & Outbox Engine and `ResourceOwnershipGuard` are deployed and verified.

### Q2: What instructor capabilities already exist?
- **RBAC Role:** Role `instructor` exists in `roles` table; seeded educator Dr. Sarah Mitchell (`instructor@techsprout.edu`) is configured.
- **Course Authoring API:** `CoursesController`, `ModulesController`, `LessonsController`, `QuizzesController`, `QuestionsController`, and `OptionsController` allow `@Roles('admin', 'instructor')` with `@RequireOwnership`.
- **Media Ingestion:** Cloudinary upload endpoints track `media.uploaderId` and restrict deletions to the uploader.
- **Backend Roster API:** `GET /api/v1/admin/courses/:id/enrollments` supports course ownership verification and returns paginated student progress.

### Q3: What are the most important instructor workflow gaps?
1. Missing dedicated frontend route tree (`/instructor/*`).
2. Missing header entry point / portal switcher for educators.
3. 403 Forbidden navigation leak on `AdminNav` Overview tab.
4. Static, dead course publication review notice with no state machine or review queue.
5. Missing student roster screen on the frontend.
6. Missing instructor profile, bio, credentials, and public avatar entity.

### Q4: What should be included in P6.2 MVP?
- **Dedicated Route Tree:** `/instructor/dashboard`, `/instructor/courses`, `/instructor/courses/new`, `/instructor/courses/[id]`, `/instructor/courses/[id]/learners`, `/instructor/profile`.
- **Navigation Fixes:** Role-aware Header switcher; `InstructorNav`; fixing 403 leak in `AdminNav`.
- **Course Review State Machine:** Adding `'IN_REVIEW'` to `course_status` enum; creating `course_review_requests` table; interactive submission modal and admin review queue.
- **Learner Roster Screen:** Interactive student table with progress percentages and CSV download.
- **Instructor Profile:** Additive `instructor_profiles` table, profile editor, and public bio component.
- **Notification Integration:** Outbox events for review submission, approval, and rejection.

### Q5: What should explicitly be excluded or deferred?
- **DEFERRED to P6.3:** Advanced Learning Analytics (drop-off curves, video watch heatmaps, quiz discrimination).
- **DEFERRED to P6.4:** Discussion forums, student assignment submissions, and manual grading rubrics.
- **DEFERRED to P7:** Instructor revenue share, wallet payouts, bKash integration, and multi-instructor co-teaching.
- **OUT OF SCOPE:** Real-time WebRTC/Zoom video streaming and automated AI curriculum generation.

### Q6: What architecture and schema changes are genuinely necessary?
Only **three additive, forward-only schema enhancements** are required:
1. `ALTER TYPE course_status ADD VALUE 'IN_REVIEW' AFTER 'DRAFT';`
2. New table `course_review_requests` (tracks submissions, review decisions, admin feedback, and timestamps).
3. New table `instructor_profiles` (tracks headline, bio, credentials, social links, and avatar).
Zero destructive migrations, zero column alterations, and zero changes to financial or order tables.

### Q7: What security and ownership risks exist?
- **Horizontal Privilege Escalation (IDOR):** An instructor attempting to modify or view another instructor's course, curriculum, or roster.  
  *Mitigation:* Strict enforcement of `ResourceOwnershipGuard` with server-derived identity (`req.user.id`).
- **Mutation During Review:** An instructor modifying course content while an institutional administrator is auditing it.  
  *Mitigation:* State machine lock: reject all course mutations while status is `'IN_REVIEW'`.

### Q8: How will P1–P6.1 behavior be protected?
- Financial invariants remain strictly untouched (no changes to SSLCommerz, invoices, or refund processing).
- The existing 1,195 test suite will be run before and after every work package.
- Curriculum authoring components are reused, preventing divergence between student catalog views and instructor editing views.

### Q9: What is the proposed implementation sequence and effort estimate?
- **7 Reviewable Work Packages:**
  - WP-01: Schema & Contracts Foundation (4–6 h)
  - WP-02: Backend API & Review State Machine (8–12 h)
  - WP-03: Frontend IA & Navigation Fixes (6–8 h)
  - WP-04: Course Review Workflow & UI (8–10 h)
  - WP-05: Learner Roster UI & CSV Export (6–8 h)
  - WP-06: Instructor Profile & Catalog Bio (6–8 h)
  - WP-07: E2E Verification & Release Gate (6–8 h)
- **Total Effort Estimate:** **44–60 engineer-hours (5.5–7.5 engineer-days)**.

### Q10: What acceptance criteria must be satisfied?
- 100% of the 1,195 existing tests must pass.
- At least 40 new automated tests must be added (reaching ≥ 1,235 passing tests).
- Zero 403 Forbidden errors when an instructor navigates the instructor portal.
- Submitting a course for review locks curriculum and creates an admin review queue item.
- Enrolled students appear in the instructor roster with verified progress percentages.
- Staging smoke tests pass cleanly on live staging infrastructure.

### Q11: What dependencies, limitations, or decisions require senior approval?
- **Decision DEC-P6.2-02:** Confirmation of Institutional Review Gate (`IN_REVIEW`) vs. Open Self-Publishing (Recommended: Institutional Review Gate).
- **Decision DEC-P6.2-03:** Confirmation of Single Instructor per Course in P6.2 vs. Multi-Instructor Sharing (Recommended: Single Instructor for MVP, defer multi-ownership to P7).
- **Staging Media Limitation:** Acknowledge that live staging media uploads remain restricted to mock/seeded assets to preserve Cloudinary production quotas.

### Q12: Is the proposal ready for implementation approval, or are further investigations required?
**The proposal is 100% complete, fully evidenced, and ready for senior review and implementation approval.** No further research is required.

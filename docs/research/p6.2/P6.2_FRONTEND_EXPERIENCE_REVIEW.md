## 1. Information Architecture & Navigation Strategy

### 1.1 The Existing Structural Defect
In the current application, educators are forced to use the `/admin/*` route tree:
- **Navigation Leak:** `AdminNav.tsx` renders an "Overview" tab pointing to `/dashboard/admin/overview`. This page enforces `user.role === 'admin'`, throwing an immediate **403 Forbidden Access Denied** error when clicked by an instructor.
- **Header Omission:** `Header.tsx` only provides links to "My Courses" (student view) and "Orders" (student purchase history). Educators have no menu link to reach their course management tools.

### 1.2 Proposed Route Tree Structure
To cleanly resolve these issues, P6.2 introduces a dedicated `/instructor/*` route tree in `apps/web/src/app`:

```
apps/web/src/app/
├── (authentication)/
├── admin/                     # Preserved for institutional administrators
│   ├── categories/
│   ├── coupons/
│   ├── courses/               # Admin catalog oversight & review queue
│   ├── finance/
│   └── layout.tsx
├── instructor/                # NEW P6.2 Dedicated Instructor Platform
│   ├── layout.tsx             # Role-gated layout (Instructor & Admin)
│   ├── dashboard/             # Aggregated instructor metrics & active alerts
│   │   └── page.tsx
│   ├── courses/               # List of courses owned by authenticated educator
│   │   ├── page.tsx
│   │   ├── new/               # Course creation wizard
│   │   │   └── page.tsx
│   │   └── [id]/              # Course workspace & curriculum management
│   │       ├── page.tsx
│   │       └── learners/      # Student enrollment roster & progress
│   │           └── page.tsx
│   └── profile/               # Educator bio, credentials & avatar
│       └── page.tsx
├── dashboard/                 # Retained for student learning overview
└── courses/                   # Public catalog
```

## 2. Screen Specifications & Blueprint

### Screen 1: Instructor Dashboard (`/instructor/dashboard`)
- **User Goal:** Give the instructor an immediate, comprehensive overview of their teaching portfolio, active review statuses, and student enrollment totals.
- **Current Status:** Missing (currently lands on static student `/dashboard`).
- **Required Information:**
  - Active Courses Count (Published).
  - Draft Courses Count (In creation).
  - Courses Pending Review (In review queue).
  - Total Enrolled Students across all owned courses.
  - Quick action: "Create New Course" button.
  - Recent activity feed (recent enrollments and review feedback alerts).
- **API Dependencies:** `GET /api/v1/instructor/dashboard`.
- **States:**
  - *Loading:* Pulse skeleton cards for the 4 primary metric boxes.
  - *Empty:* Welcoming hero card with call-to-action: *"Ready to share your knowledge? Create your first course to get started."*
  - *Error:* Alert banner with retry button.
- **Accessibility & Responsive:** Fully responsive CSS grid (1 column on mobile `<640px`, 2 on tablet `<1024px`, 4 on desktop). Valid aria headings (`h1` for page title, `h2` for metric sections).

---

### Screen 2: Instructor Course List (`/instructor/courses`)
- **User Goal:** Search, filter, and view all courses authored by the instructor, showing real-time lifecycle status badges and enrollment counts.
- **Current Status:** Partially implemented under `/admin/courses`, but cluttered with admin-only controls (category management, bulk price overrides).
- **Required Information & Actions:**
  - Course card/row: Thumbnail, Title, Category, Price (BDT), Status badge (`DRAFT` [amber], `IN_REVIEW` [blue], `PUBLISHED` [emerald], `ARCHIVED` [slate]), Enrolled student count, Last updated date.
  - Action buttons: "Edit Curriculum", "View Learners", "Delete Draft" (draft only).
  - Status filter tabs: `All`, `Draft`, `In Review`, `Published`.
  - Search input with debounce.
- **API Dependencies:** `GET /api/v1/instructor/courses?status={status}&search={search}&page={page}`.
- **States:**
  - *Loading:* Skeleton rows.
  - *Empty:* Clean empty state with "No courses found matching filter" or "Create your first course".
- **Security Check:** Server strictly filters `where: courses.instructor_id === req.user.id`.

---

### Screen 3: Course Workspace & Curriculum Management (`/instructor/courses/[id]`)
- **User Goal:** Complete course authoring workspace where the educator edits course metadata, organizes modules, drafts lessons, uploads videos/resources, and creates quizzes.
- **Current Status:** Currently located at `/admin/courses/[id]`.
- **Key Experience Improvements for P6.2:**
  - **Component Reuse:** Directly reuse the robust curriculum authoring components ([CurriculumTab.tsx](file:///d:/Work/2026/techsprout-main/apps/web/src/components/admin/CurriculumTab.tsx), [ModuleList.tsx](file:///d:/Work/2026/techsprout-main/apps/web/src/components/admin/ModuleList.tsx), [LessonItem.tsx](file:///d:/Work/2026/techsprout-main/apps/web/src/components/admin/LessonItem.tsx)).
  - **Replaced Publishing Actions:** Replace the dead static notice in `PublishingActions.tsx` with an interactive "Submit for Review" modal:
    - Displays curriculum completeness checklist:
      - [x] Course title & description.
      - [x] Thumbnail uploaded.
      - [x] At least 1 module with published lessons.
      - [x] Valid pricing (BDT).
    - Optional "Submission Notes for Reviewer" text area.
    - Status banner displaying review progress: *"Under Review by Institutional Administrators since Oct 10, 2026"*.
    - Rejection feedback alert: If rejected, displays prominent notice with admin comments and "Re-submit" button once updated.
- **API Dependencies:**
  - `GET /api/v1/courses/:id`
  - `PATCH /api/v1/admin/courses/:id`
  - `POST /api/v1/instructor/courses/:id/submit-for-review`
- **Ownership Invariant:** Protected by `@RequireOwnership('course', 'id')`.

---

### Screen 4: Student Roster & Progress (`/instructor/courses/[id]/learners`)
- **User Goal:** Monitor student engagement, view individual completion progress, and export learner records for academic reporting.
- **Current Status:** Missing frontend screen (Backend API `GET /api/v1/admin/courses/:id/enrollments` already implemented).
- **Required Information & Actions:**
  - Header: Course Title, Total Enrolled, Active Learners, Completed Learners.
  - Roster Table:
    - Student Name & Email.
    - Enrollment Date (formatted).
    - Status Badge: `ACTIVE` (blue), `COMPLETED` (green), `CANCELLED` (gray).
    - Progress Bar: Percentage completion with numeric badge (`75%`).
    - Certificate Status: Yes (with date) / No.
  - Filter by enrollment status (`ALL`, `ACTIVE`, `COMPLETED`).
  - Search by student name or email.
  - "Export Roster (CSV)" button triggering client-side or streaming CSV generation.
- **API Dependencies:** `GET /api/v1/admin/courses/:id/enrollments?page={page}&limit=20&status={status}&search={search}`.
- **States:**
  - *Loading:* Skeleton table rows.
  - *Empty:* *"No students enrolled yet. Once your course is published and students enroll, their progress will appear here."*
- **Accessibility:** Accessible `<table>` markup with proper `<th>` scope, aria-labels for progress bars, keyboard navigable pagination controls.

---

### Screen 5: Instructor Profile & Credentials (`/instructor/profile`)
- **User Goal:** Allow educators to manage their professional bio, academic qualifications, and verified public presence.
- **Current Status:** Missing.
- **Required Fields:**
  - Headline (e.g., *"Senior Full-Stack Engineer & Computer Science Lecturer"*).
  - Professional Bio (Markdown or formatted text, max 2,000 characters).
  - Academic Credentials (e.g., *"B.Sc. CSE (BUET), M.Sc. Software Engineering"*).
  - Professional Links: LinkedIn URL, GitHub URL, Personal Website.
  - Profile Avatar / Photo (uses existing Cloudinary media uploader).
- **API Dependencies:** `GET /api/v1/instructor/profile` and `PATCH /api/v1/instructor/profile`.
- **Display Integration:** Displayed on public course detail page (`/courses/[slug]`) in the "About the Instructor" section.

---

### Screen 6: Administrator Review Queue (`/admin/courses`)
- **User Goal:** Enable institutional administrators to audit submitted courses, inspect curriculum standards, and approve or reject publication.
- **Current Status:** Admin course page only lists DRAFT, PUBLISHED, ARCHIVED with direct publish buttons.
- **Required Enhancements:**
  - Add "In Review" filter tab with counter badge (e.g., `In Review (3)`).
  - Course review modal with two distinct actions:
    1. **"Approve & Publish":** Prompts confirmation modal; immediately transitions course to `PUBLISHED` and alerts instructor.
    2. **"Request Revisions / Reject":** Opens modal requiring structured revision feedback notes; transitions course back to `DRAFT` and alerts instructor with notes.
- **API Dependencies:** `GET /api/v1/admin/courses/review-queue`, `POST /api/v1/admin/courses/:id/approve-review`, `POST /api/v1/admin/courses/:id/reject-review`.

## 3. Component Architecture & Reuse Strategy

To avoid redundant code and maintain design consistency:
1. **`InstructorLayout.tsx`:** Standard layout wrapping all `/instructor/*` pages. Enforces session check and `role === 'instructor' || role === 'admin'`. Renders `Hero` and `InstructorNav`.
2. **`InstructorNav.tsx`:** Clean navigation bar containing tabs:
   - `Dashboard` (`/instructor/dashboard`)
   - `My Courses` (`/instructor/courses`)
   - `Profile` (`/instructor/profile`)
3. **`CourseReviewModal.tsx`:** Reusable modal handling checklist verification and review submission.
4. **`LearnerRosterTable.tsx`:** Paginated, responsive table component with search and CSV export.
5. **No Disruptions to Student or Admin UI:** Student dashboards and public catalog pages remain completely untouched, ensuring zero regressions for learners.

## 4. Real PostgreSQL 16 Migration Validation & Database Isolation

### 4.1 Real PostgreSQL 16 CI Migration & DDL Gate (Hardened Isolation & 12-Migration Journal Validation)
In addition to the previous `pg-mem` static tests, PR #4 introduces a dedicated, fail-closed validation gate executed against a genuine disposable PostgreSQL 16 service container (`postgres:16-alpine`):

- **Dedicated Test Suite:** [`apps/api/src/test/real-postgres-migration.spec.ts`](file:///d:/Work/2026/techsprout-main/apps/api/src/test/real-postgres-migration.spec.ts)
- **CI Step:** `Verify Real PostgreSQL 16 Migration Validation & DDL Gate (0000-0011)` in [`.github/workflows/ci.yml`](file:///d:/Work/2026/techsprout-main/.github/workflows/ci.yml)
- **Unique Database Name Generation:** Uses a cryptographically random collision-resistant identifier (`crypto.randomBytes(6).toString('hex')` producing `techsprout_mig_<12_hex_chars>`) for every test execution, preventing naming collisions or concurrency interference across parallel runs.
- **Pre-Creation Collision Check:** Explicitly confirms via `SELECT 1 FROM pg_database WHERE datname = $1` that the uniquely named database does not already exist before executing `CREATE DATABASE`.
- **Target Safety Assertion:** `assertDisposableDatabaseSafety` verifies that the target connection string points strictly to `localhost`, `127.0.0.1`, or `postgres` with a database name containing `test`, `disposable`, or `temp`. Any target mentioning cloud providers (`render.com`, `aws`, `supabase`, `neon.tech`, `railway`, `elephantsql`, `cockroachlabs`, etc.) or `prod`/`staging` throws an immediate fatal safety violation. All credentials, usernames, and passwords are strictly suppressed from error messages.
- **Service Container Version Verification:** Connects to the base PostgreSQL instance and verifies `SELECT version()` explicitly contains `PostgreSQL 16`. Fails closed if executed against an unintended PostgreSQL major version.
- **Environment Gating & Transparent Skip Semantics:**
  - In GitHub Actions (`GITHUB_ACTIONS === 'true'`), requires the explicit disposable container flag `CI_DISPOSABLE_POSTGRES === 'true'`; if absent, fails immediately with a fatal gate error (`FAIL-CLOSED GATE`).
  - Outside explicitly configured disposable test environments (local developer machines without `CI_DISPOSABLE_POSTGRES=true`), Vitest cleanly marks the entire specialized suite as `[skipped]` (`7 skipped`) with an actionable console notice. It **never** silently claims real PostgreSQL validation passed when skipped.
- **Safe Lifecycle & Zero Connection Disruption:**
  - Destructive `pg_terminate_backend` statements have been completely eliminated. The suite **never** forcefully terminates connections belonging to existing or unrelated database sessions.
  - Tracks whether this execution successfully created the dedicated database (`dbCreatedByThisRun = true`).
  - Only drops the database in `afterAll` if created by this execution and after its own pool connections have been closed.
  - If database drop fails during teardown, a diagnostic warning is logged without forcefully killing connections or aborting unrelated databases.
- **Comprehensive Migration Journal & Ledger Verification (0000 through 0011):**
  - Loads all entries from `apps/api/src/database/migrations/meta/_journal.json`.
  - Reads each migration SQL file from disk from `0000_initial_schema.sql` through `0011_discussions_and_assignments.sql`.
  - Computes the SHA-256 hash using Drizzle ORM's exact serialization and hashing algorithm (`crypto.createHash('sha256').update(fileContent).digest('hex')`).
  - Verifies that `drizzle.__drizzle_migrations` contains all 12 expected entries.
  - Compares each recorded migration hash against the corresponding migration file's SHA-256 hash.
  - Compares each recorded migration timestamp (`created_at`) against the corresponding journal timestamp (`when`).
  - Validates sequential ordering across all 12 migrations (`Number(row.id) === i + 1`).
  - Fails with an explicit diagnostic error identifying the first mismatched migration (index, tag, expected vs recorded values).
- **Verified DDL, Constraints & Triggers:**
  - **Schema Completeness:** Proves all 45 required relational tables and 10 custom ENUM types exist in PostgreSQL `information_schema` and `pg_type`.
  - **Ledger Immutability Triggers:** Confirms that `trg_immutable_ledger_transactions` and `trg_immutable_ledger_entries` trigger fatal exceptions upon attempted `UPDATE` or `DELETE` on posted transactions or entries.
  - **CHECK Constraints:** Validates that negative wallet balances, non-BDT currencies, zero/negative entry amounts, and SETTLED payout requests with missing/short settlement references ($\ge 3$ chars) are rejected by PostgreSQL kernel check constraints.
  - **Foreign Key Cascades & Restrictions:** Validates that discussion reply deletions cascade from discussions, assignment submission deletions cascade from assignments, and user deletions are blocked (`ON DELETE RESTRICT`) when financial wallets exist.
  - **Transaction Rollback:** Validates that transactional `ROLLBACK` (both explicit and error-aborted) cleanly discards uncommitted data in real PostgreSQL.

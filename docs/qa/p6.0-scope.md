## 1. P6 Master Objective

The overarching objective of **Phase 6** is to elevate TechSprout from an *admin-curated, single-vendor commerce LMS* into a *scalable, multi-role educational platform* with decoupled asynchronous event-driven notifications, an autonomous instructor ecosystem with zero-trust resource-level authorization, and pedagogical interactions (discussions & project assignments).

---

## 2. Definitive Scope Categorization

### 2.1 MUST HAVE (Critical Core for Phase 6)
1. **Asynchronous Notification & Event Platform (P6.1):**
   - Decoupled domain events emitted from orders, payments, refunds, and certificates.
   - BullMQ worker processing `techsprout-notifications` queue with exponential backoff and DLQ.
   - Transactional email dispatch (integration with Resend/Postmark/SendGrid).
   - In-app notification center (DB table `notifications`, unread counters, mark-as-read API, UI bell icon).
   - Notification preferences (user-controlled opt-outs for non-transactional alerts).
2. **Resource-Level Authorization & Zero-Trust Ownership (P6.1/P6.2):**
   - Contextual `ResourceOwnershipGuard` validating `course.instructorId` across modules, lessons, quizzes.
   - Media asset ownership scoping (`uploader_id` attached to media uploads to prevent unauthorized reuse/deletion).
3. **Dedicated Instructor Subsystem & Portal (P6.2):**
   - Segregated UI routes under `/instructor` (`overview`, `courses`, `curriculum`, `learners`).
   - `instructor_profiles` entity storing pedagogical bio, headline, and public details.
   - Full curriculum authoring UI (module creation, lesson uploads, quiz builders) for assigned courses.
4. **Course Publication & Quality Review Workflow (P6.2):**
   - Addition of `IN_REVIEW` course status enum.
   - Instructor "Submit for Review" workflow with pre-submission validation checklist.
   - Admin "Review & Publish" queue with one-click approve or rejection reason feedback.

### 2.2 SHOULD HAVE (High-Value Follow-on within Phase 6)
1. **Append-Only Learning Analytics Engine (P6.3):**
   - Event logging table `learning_events` capturing lesson starts, video milestones, completions.
   - Instructor course analytics dashboard (enrollment growth, completion funnel, drop-off hotspots).
   - Student personal learning streak and weekly engagement metrics on `/dashboard`.
2. **Interactive Lesson Discussions / Q&A (P6.4):**
   - Threaded question-and-answer subsystem attached to individual lessons.
   - Student question posting, instructor reply badge, peer upvoting, and instructor moderation.
   - Automatic in-app notification when an instructor replies to a student question.
3. **Hands-on Assignments & Project Submissions (P6.4):**
   - Assignment activity type sibling to quizzes (due date, prompt, rubric).
   - Student project submission (file upload or repository URL).
   - Instructor grading interface with numeric score and qualitative feedback.

### 2.3 COULD HAVE (Stretch Capabilities for Late P6)
1. **Course Announcements Board:**
   - 1-to-many broadcast announcement tool allowing instructors to message all active enrolled learners.
2. **Enhanced Learner Notes:**
   - Private personal timestamped notes taken by students inside the classroom player.

### 2.4 DEFERRED (Explicitly Moved to Phase 7 or Later)
1. **Recurring Billing & Subscriptions:**
   - Monthly/annual subscription plans and dunning management. Deferred to preserve P5.5 financial stability.
2. **Multi-Currency & International Gateways:**
   - Processing USD/EUR via Stripe or Paddle. BDT via SSLCommerz remains standard.
3. **Course Prerequisites & Career Tracks:**
   - Gated course dependency chains. Deferred until catalog scale exceeds 50+ courses.
4. **AI Tutoring & Automated Assistants:**
   - LLM chat assistants, AI quiz generation. Deferred until structured event data and knowledge embeddings are mature.
5. **Automated Instructor Revenue Share & Marketplace Wallets:**
   - Multi-vendor split payments and automated MFS payouts. Deferred due to local regulatory/tax compliance requirements.

### 2.5 REJECTED / PERMANENTLY OUT OF SCOPE
1. **SCORM / LTI Enterprise Packaging:** Unnecessary complexity for modern cloud-native consumer/B2C LMS.
2. **Live Video Streaming Infrastructure (WebRTC / RTMP servers):** Out of scope; live classes integrate via external meeting links (Zoom/Google Meet/YouTube Live).

## 4. P6 Acceptance Gates

Before implementation commits for any P6 milestone are merged, the following formal gates must pass:

### 4.1 Product Gate
- [ ] Explicit user personas approved (Student, Instructor, Administrator).
- [ ] Core user flows approved (Instructor publishes course -> Admin approves -> Student enrolls -> Notification delivered).
- [ ] Exclusions strictly frozen (no subscriptions, no AI chatbots in P6).

### 4.2 Architecture Gate
- [ ] Modular monolith boundaries maintained within NestJS.
- [ ] Transactional Outbox / BullMQ decoupled event pattern validated.
- [ ] Zero blocking external IO in transactional endpoints.

### 4.3 Database Gate
- [ ] Drizzle ORM schemas define strict foreign keys, cascading rules, and unique constraints.
- [ ] Forward and backward migration scripts verified against PostgreSQL 16.
- [ ] Retention and indexing policies defined for `notifications` and `learning_events`.

### 4.4 Security Gate
- [ ] Contextual `ResourceOwnershipGuard` enforces `course.instructorId` on all child resource mutations.
- [ ] Media assets strictly scoped by `uploader_id`.
- [ ] All user inputs validated with Zod schemas (`strict()` where appropriate to reject mass assignment).
- [ ] Zero IDOR vulnerabilities across student, instructor, and admin surfaces.

### 4.5 Implementation Gate
- [ ] Automated regression tests pass 100% (target >1,350 total tests).
- [ ] Production builds clean with zero lint errors or TypeScript warnings.
- [ ] Staging verification confirmed on Render and Vercel before production deployment.

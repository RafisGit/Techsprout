## 1. OBJECTIVE

The objective of P5.5.7 is to implement the authoritative **Admin Financial CSV Export** capability (`GET /api/v1/admin/finance/export`) for the TechSprout LMS platform. This provides finance administrators with real-time, streaming, RFC 4180-compliant CSV exports across three financial reporting domains:
1. `orders`: Authoritative order, billing, and payment records.
2. `refunds`: Authoritative refund execution records and gateway transaction tracking.
3. `reconciliation`: Authoritative gateway-to-ledger audit scans and discrepancy logs.

The implementation strictly enforces enterprise financial safety, zero state mutation, zero gateway calls, strict admin RBAC authorization, a maximum 90-day export window, a 10,000-row protective ceiling, and immutable streaming delivery.

1. **`orders`**:

   - Accurately captures refund states (`PENDING`, `PROCESSED`, `FAILED`).

   - Authoritative reconciliation discrepancy and gateway health scans executed in read-only dry-run mode.
   - Deterministic columns:

## 4. API CONTRACT

### Shared Schema (`packages/contracts/src/index.ts`)
```typescript
export const financeExportTypeSchema = z.enum(['orders', 'refunds', 'reconciliation']);
export type FinanceExportType = z.infer<typeof financeExportTypeSchema>;

export const financeExportQuerySchema = z.object({
  type: financeExportTypeSchema,
  startDate: z.string().optional(),
  endDate: z.string().optional(),
});
export type FinanceExportQuery = z.infer<typeof financeExportQuerySchema>;
```

### HTTP Endpoint
- **Method & Path:** `GET /api/v1/admin/finance/export`
- **Query Parameters:**
  - `type` (required): `'orders' | 'refunds' | 'reconciliation'`
  - `startDate` (optional): ISO 8601 string or `YYYY-MM-DD`
  - `endDate` (optional): ISO 8601 string or `YYYY-MM-DD`
- **Headers:**
  - `Content-Type: text/csv; charset=utf-8`
  - `Content-Disposition: attachment; filename="techsprout-<type>-<startDate>-to-<endDate>.csv"`
  - `Transfer-Encoding: chunked`
- **Error Responses:**
  - `401 Unauthorized`: Missing or invalid session cookie.
  - `403 Forbidden`: Authenticated student or non-admin attempting access.
  - `400 Bad Request`: Validation errors (`INVALID_DATE`, `INVALID_DATE_RANGE`, `DATE_RANGE_EXCEEDED`, `EXPORT_SIZE_EXCEEDED`).
  - `429 Too Many Requests`: Rate limit exceeded (>10 requests/minute).

## 5. DATE-RANGE BEHAVIOR

- **Server-Side Parsing:** Handled by `validateAndNormalizeDateRange(startDateStr, endDateStr)`.
- **UTC Normalization:**
  - `startDate` is normalized to the beginning of the UTC day (`00:00:00.000Z`).
  - `endDate` is normalized to the end of the UTC day (`23:59:59.999Z`).
- **Inclusive Boundaries:** Queries apply `gte(schema.orders.createdAt, startUtc)` and `lte(schema.orders.createdAt, endUtc)`.
- **Validation:**
  - Ambiguous or malformed date strings return `400 INVALID_DATE`.
  - If `startDate > endDate`, returns `400 INVALID_DATE_RANGE`.
  - Date window exceeding 90 days returns `400 DATE_RANGE_EXCEEDED`.

---

## 6. 90-DAY & 10,000-ROW LIMITS

- **90-Day Ceiling:** Enforced mathematically:
  ```typescript
  const diffDays = Math.ceil((endUtc.getTime() - startUtc.getTime()) / (1000 * 60 * 60 * 24));
  if (diffDays > 90) {
    throw new BadRequestException({
      errorCode: 'DATE_RANGE_EXCEEDED',
      message: `Requested export date range (${diffDays} days) exceeds maximum allowed limit of 90 days.`,
    });
  }
  ```
- **10,000-Row Ceiling:** An authoritative `count()` query executes against indexed database columns prior to streaming. If matching rows exceed 10,000, execution halts with:
  ```typescript
  throw new BadRequestException({
    errorCode: 'EXPORT_SIZE_EXCEEDED',
    message: `Export query matches ${count} records which exceeds the maximum limit of 10,000. Please narrow your date range.`,
  });
  ```
  No silent truncation occurs; administrators receive an explicit error directing them to narrow their filter.

## 7. STREAMING ARCHITECTURE

```
Database Query (Indexed / Filtered)
          ↓
Iterative Row Generator
          ↓
FinanceCsvService.transformToCsvStream()
  - Prepends UTF-8 BOM (\uFEFF)
  - Emits Deterministic Header Row + CRLF
  - Transforms & Escapes each row chunk into PassThrough
          ↓
NestJS StreamableFile (PassThrough Stream)
          ↓
HTTP Response (Transfer-Encoding: chunked)
```
- Memory footprint is strictly bounded (O(chunk) instead of O(N)).
- Node.js event loop remains responsive with zero unbounded string concatenations and zero temporary file creation on disk.

---

## 8. CSV FORMAT & ESCAPING

- **RFC 4180 Escaping:** Handled by `FinanceCsvService.escapeCell()`:
  - If a cell contains commas (`,`), double quotes (`"`), carriage returns (`\r`), or newlines (`\n`), it is wrapped in double quotes.
  - Existing double quotes are escaped by doubling them (`""`).
- **Line Endings:** RFC 4180 standard CRLF (`\r\n`).
- **Excel Compatibility:** All CSV streams begin with UTF-8 Byte Order Mark (`\uFEFF`).
- **Unicode & Bengali:** Bengali script (e.g. `বাংলা কোর্স`, `শিক্ষার্থী মন্তব্য`) is preserved without degradation or character corruption.

---

## 9. MONEY REPRESENTATION

- **Canonical Standard:** TechSprout standard monetary formatting (`BDT <amount>`).
- Subtotals, discounts, payable totals, and refund amounts are formatted using `formatMoney(minorUnits, 'BDT')` (e.g. `BDT 5000.00`), ensuring exact alignment with invoices and finance dashboard displays.
- All values are sourced directly from historical minor-unit columns in the database without mutating historical state.

## 10. ADMIN AUTHORIZATION & RBAC

- Endpoint is guarded by `@UseGuards(JwtAuthGuard, RolesGuard)` and decorated with `@Roles(UserRole.ADMIN)`.
- Verified behaviors:
  - Unauthenticated anonymous requests return `401 Unauthorized`.
  - Authenticated students (`UserRole.STUDENT`) return `403 Forbidden`.
  - Non-admin JWT tokens are rejected server-side.
  - Authorized administrators (`UserRole.ADMIN`) have complete export access.

## 11. DATA PROTECTION & ZERO SECRETS LEAKAGE

- Exports expose only legitimate financial reporting columns.
- Explicitly excluded from CSV outputs:
  - Student passwords and password hashes.
  - User session tokens and refresh tokens.
  - SSLCommerz gateway credentials (`storeId`, `storePassword`).
  - Raw gateway request and response payloads.
  - Internal database IDs (e.g. internal foreign key UUIDs are kept private; only human-readable `orderNumber` and `refundNumber` are exposed).

  - `targetType`: `'finance_export'`
  - `targetId`: Export type (`'orders'`, `'refunds'`, `'reconciliation'`)
  - `metadata`:
    ```json
    {
      "exportType": "orders",
      "startDate": "2026-09-01T00:00:00.000Z",
      "endDate": "2026-10-06T23:59:59.999Z",
      "recordCount": 142,
      "generatedAt": "2026-10-06T17:15:00.000Z"
    }
    ```
- Audit log persistence never logs CSV payload content or payment secrets.

## 19. PERFORMANCE CONSIDERATIONS

- Queries utilize existing database indices on `createdAt`, `status`, and foreign keys.
- Streaming via Node.js `PassThrough` stream avoids buffering large CSV payloads into memory.
- The 90-day time window and 10,000-row volume cap ensure database query execution times stay under 250ms even under peak reporting loads.
- Rate limiting at 10 requests/minute per admin safeguards against unintended denial-of-service or scraping scripts.

---

## 20. KNOWN LIMITATIONS

- Exports are synchronous streams. Very large background batch exports (e.g., millions of records spanning multiple years) would require an asynchronous worker queue (such as BullMQ) and object storage (S3/GCS); however, per P5.5 frozen architecture specifications, the 90-day/10,000-row cap deliberately renders this unnecessary.
- Browser download depends on standard HTML5 `Blob` and `a[download]` support, which is universally supported in modern browsers.

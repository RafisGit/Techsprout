  - `InvoicesService`: Read-only queries, ownership checks, pagination metadata calculation, search/filter queries, and historical snapshot mapping.

- **Side-Effect-Free Read-Only Guarantees**:
  - Zero database mutations occur during any invoice GET request.
  - No records are inserted, deleted, or updated.
  - Invoices, orders, payments, enrollments, and coupons remain untouched during retrieval.

## 4. API Endpoints Implemented

### 1. `GET /api/v1/invoices`
- **Caller**: Authenticated student
- **Security**: Guarded by `AuthGuard`
- **Behavior**: Retrieves paginated invoices strictly matching `invoices.student_id = req.user.id`.
- **Query Parameters**: `page` (default 1), `limit` (default 20, max 100), `status`, `search`, `startDate`, `endDate`.
- **Response**: `200 OK` with standard `PaginatedInvoicesResponse`.

### 2. `GET /api/v1/invoices/:id`
- **Caller**: Authenticated student owner OR admin
- **Security**: Guarded by `AuthGuard` + Service Ownership Check
- **Behavior**:
  - If `user.role !== 'admin' && invoice.studentId !== user.id` $\rightarrow$ `403 Forbidden` (`INVOICE_ACCESS_DENIED`).
  - If invoice not found $\rightarrow$ `404 Not Found` (`INVOICE_NOT_FOUND`).
  - If malformed UUID $\rightarrow$ `400 Bad Request` (`INVALID_ID`).
- **Response**: `200 OK` with standard `InvoiceDetailResponse`.

### 3. `GET /api/v1/admin/invoices`
- **Caller**: Authenticated administrator
- **Security**: Guarded by `AuthGuard` + `RolesGuard` (`@Roles('admin')`)
- **Behavior**: Retrieves paginated invoices across all students with administrative filters (`status`, `search`, `startDate`, `endDate`). Non-admins receive `403 Forbidden` (`FORBIDDEN`).
- **Response**: `200 OK` with standard `PaginatedInvoicesResponse`.

### 4. `GET /api/v1/admin/invoices/:id`
- **Caller**: Authenticated administrator
- **Security**: Guarded by `AuthGuard` + `RolesGuard` (`@Roles('admin')`)
- **Behavior**: Retrieves any single invoice by ID. Non-admins receive `403 Forbidden` (`FORBIDDEN`).
- **Response**: `200 OK` with standard `InvoiceDetailResponse`.

## 5. Authorization Model

- **Authentication**: TechSprout standard `AuthGuard` via `techsprout_session` HttpOnly cookie or `Bearer` token.
- **RBAC**: Project-standard `RolesGuard` with `@Roles('admin')`.
- **Data Isolation**:
  - In student queries, `WHERE invoices.student_id = :studentId` is hardcoded at the SQL query level, completely preventing cross-tenant leakage.
  - In detail queries, cross-student access attempts trigger `403 Forbidden` with errorCode `INVOICE_ACCESS_DENIED` without leaking whether another student's invoice exists.
  - Non-admin attempts to access `/api/v1/admin/invoices` are rejected at the guard level with `403 Forbidden` (`FORBIDDEN`).

## 6. Pagination & Filtering

- **Pagination Format**: Project-standard `PaginationMetadata`:
  ```json
  {
    "page": 1,
    "limit": 20,
    "total": 42,
    "totalPages": 3,
    "hasNextPage": true,
    "hasPreviousPage": false
  }
  ```
- **Empty Result Handling**: Returns `items: []`, `total: 0`, `totalPages: 1`, `hasNextPage: false`, `hasPreviousPage: false`.
- **Admin Filtering**:
  - `status`: Filters by `PAID`, `REFUNDED`, or `VOID`.
  - `startDate` / `endDate`: Filters by `issued_at` timestamp range using `gte` and `lte`.
  - `search`: Case-insensitive `ILIKE` pattern across `invoice_number`, `student_name`, `student_email`, and `course_title`.

## 7. Snapshot Immutability Verification

Financial data integrity was verified via targeted tests:
1. **Course Mutation Test**: Modifying the catalog course title (e.g. from `"Fullstack TypeScript Architecture"` to `"MUTATED"`) and altering the catalog price from `2500.00` to `9999.00` had zero effect on the invoice. Subsequent `GET /api/v1/invoices/:id` returned the original historical title and pricing.
2. **Student Profile Mutation Test**: Renaming the student user and altering their registered email address in the `users` table had zero effect on the invoice snapshot. The invoice continued returning the snapshot name and email captured at the time of purchase.
3. **No Dynamic Joins**: `InvoicesService` reads directly from the `invoices` table without dynamic catalog or profile joins that could corrupt financial history.

## 8. Zero-Payable Invoice Handling

- Fully accommodates 100% coupon-discounted zero-payable orders:
  - `subtotalCents`: Historical original course price (e.g. `80000` = 800.00 BDT).
  - `discountCents`: `80000` (800.00 BDT).
  - `payableCents`: `0`.
  - `currency`: `'BDT'` (integer minor units preserved, no floating point arithmetic).
  - `paymentMethod`: `'COUPON'`.
  - `bankTranId`: `'FREE_COUPON'`.
  - `status`: `'PAID'`.

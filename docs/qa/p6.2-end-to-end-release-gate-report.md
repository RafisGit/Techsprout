## 6. Major Instructor End-to-End Workflow Results

### Workflow A: Instructor Authentication & Navigation Isolation
- **Signed-Out Access:** Visiting `/instructor/*` without session token triggers server-side redirect to `/login` via `apps/web/src/app/instructor/layout.tsx`.
- **Student Access:** Logged-in students attempting direct navigation to `/instructor/*` are intercepted by the server layout and rendered a clean `403 Forbidden` access denied page with a button to return to the student dashboard.
- **Instructor Access:** Logged-in instructors accessing `/instructor/dashboard` see aggregate educator metrics (Courses Taught, Drafts, Pending Reviews, Total Students).
- **Navigation Shell:** `InstructorNav.tsx` renders dedicated tabs (`Dashboard`, `My Courses`, `Profile`) using semantic `<nav aria-label="...">` and `aria-current="page"`.
- **Overview 403 Trap Elimination:** `AdminNav.tsx` conditionally gates the Overview tab (`show: isAdmin`). Non-admin instructors no longer see or click the Overview tab, permanently eliminating the 403 leak identified in P6.0.
- **Header Navigation:** `Header.tsx` renders "Instructor Portal" for instructors and "Admin Portal" for admins in both desktop and mobile drawer headers with zero layout flash during session hydration.

### Workflow B: Course Authoring & Review State Machine Lifecycle
- **Authoritative Instructor Binding:** When an instructor creates a course, `CoursesService.create` ignores client-supplied `instructorId` and authoritatively binds `courses.instructorId = req.user.id`.
- **Preflight Validation Gate:** `submitForReview` evaluates curriculum completeness. Courses lacking title, description, thumbnail media, $\ge 1$ module, or $\ge 1$ lesson are rejected with `400 BAD_REQUEST: INCOMPLETE_CURRICULUM` detailing all missing items.
- **Submission & State Transition:** Submitting an eligible draft course atomically updates `courses.status = 'IN_REVIEW'`, creates a `course_review_requests` record with `status = 'PENDING'`, and emits domain event `CourseSubmittedForReview`.
- **Curriculum Immutability Lock:** While `courses.status === 'IN_REVIEW'`, all mutation endpoints across courses (`PATCH /admin/courses/:id`), modules (`POST/PATCH/DELETE /admin/modules`), lessons (`POST/PATCH/DELETE /admin/lessons`), and quizzes (`POST/PATCH/DELETE /admin/quizzes`) reject updates with `400 BAD_REQUEST: COURSE_LOCKED_FOR_REVIEW`.
- **Review Queue Visibility:** Administrators querying `GET /api/v1/courses/review-queue` or viewing `/admin/courses/review-queue` see all pending submission requests with course metadata, instructor info, and submission notes.
- **Administrative Rejection:** Admin rejection requires non-empty feedback (`adminFeedback`). Rejection transitions the course back to `DRAFT`, marks the review request `REJECTED`, and emits `CourseReviewRejected`. The instructor sees the admin feedback alert banner on their course page and can edit and resubmit.
- **Administrative Approval:** Admin approval transitions the course to `PUBLISHED`, sets `courses.publishedAt = NOW()`, marks the review request `APPROVED`, and emits `CourseReviewApproved`. The course immediately appears in the public catalog.
- **Instructor Review Withdrawal:** An instructor can withdraw a pending submission via `POST /api/v1/instructor/courses/:id/withdraw-review`. The course returns to `DRAFT`, the request is marked `WITHDRAWN`, and curriculum editing unlocks immediately.

### Workflow C: Learner Roster & Progress Tracking
- **Scoped Roster Retrieval:** `GET /api/v1/admin/courses/:id/enrollments` enforces `@Roles('admin', 'instructor')` and `@RequireOwnership('course', 'id')`. Instructors can access only rosters for courses they own.
- **Progress Calculations:** Enrolled students' progress percentages (`0%` to `100%`) reflect authoritative database progress metrics calculated from completed lessons and quizzes.
- **Roster UI Presentation:** `LearnerRosterTable.tsx` renders a desktop tabular view and a responsive mobile card list with accessible progress bars (`role="progressbar"`), enrollment dates, completion dates, and status badges.
- **Empty & Error States:** Informative empty states render when no students are enrolled or when search filters return 0 results.
- **RFC-4180 CSV Export:** Clicking "Download CSV" generates an RFC-4180 compliant CSV file with a UTF-8 Byte Order Mark (`\uFEFF`) for spreadsheet Unicode compatibility. Formula injection attacks (`=`, `+`, `-`, `@`, `\t`, `\r`) are neutralized by prefixing single quotes and wrapping fields in double quotes. Multi-page courses are fetched iteratively (up to 100/page) so that no learners are omitted.

### Workflow D: Instructor Profile Management & Public Catalog
- **Profile Persistence:** Instructors manage headline, bio, academic credentials, expertise areas, and social links (Website, LinkedIn, GitHub) via `/instructor/profile`. Updates persist across sessions and page refreshes.
- **Avatar Media Scoping:** Avatar uploads verify that `media.uploader_id === req.user.id`. Selecting an asset uploaded by another user fails with `403 FORBIDDEN: MEDIA_OWNERSHIP_DENIED`. Zero Cloudinary secrets are exposed in the client.
- **Public Catalog Presentation:** Public course pages (`/courses/[slug]`) project the instructor's bio card (`InstructorBioCard.tsx`) in the "About the Instructor" section with faculty verification badges and accessible external links (`target="_blank" rel="noopener noreferrer"`).
- **Graceful Fallbacks:** If an instructor has not completed a profile, the bio card falls back cleanly to their display name, initials avatar, and institutional faculty placeholder without rendering broken images or empty fields.
- **PII Privacy Redaction:** Public responses strictly omit instructor emails, password hashes, user roles, internal media IDs, enrollment metrics, and financial records.

### IDOR & Negative Test Verification Evidence
- **Cross-Instructor Course Access:** Instructor B attempting to read, update, or delete Instructor A's draft course receives `403 FORBIDDEN` and generates audit event `UNAUTHORIZED_RESOURCE_ACCESS_ATTEMPT`.
- **Cross-Instructor Roster Access:** Instructor B requesting enrollments for Instructor A's course receives `403 FORBIDDEN`.
- **Cross-Instructor Review Mutation:** Instructor B attempting to submit or withdraw Instructor A's course review receives `403 FORBIDDEN`.

### Data-Integrity Invariants
1. **Course Status Consistency:** Transitions are strictly validated against prior state in atomic PostgreSQL transactions. Concurrent transitions fail safely with `409 CONFLICT: CONCURRENT_MODIFICATION`.
2. **Review Request Synchronization:** Exactly one `PENDING` review request can exist for an active review cycle. Approving, rejecting, or withdrawing updates both `courses.status` and `course_review_requests.status` atomically.
3. **Outbox Event Alignment:** Domain events (`CourseSubmittedForReview`, `CourseReviewApproved`, `CourseReviewRejected`) are emitted strictly post-commit.
4. **Financial Preservation:** Zero mutations to `orders`, `order_items`, `invoices`, `refund_requests`, or `payments`. All financial calculations continue using integer minor units (`moneyCents`).

## 11. Known Defects & Limitations Register

### Defect Investigation: WP-05 Learner Roster Search Scope
- **Issue:** WP-05 completion report noted that learner roster search is executed client-side because the backend does not accept a search query parameter.
- **Investigation:** Code inspection of `LearnerRosterClient.tsx` (lines 88–96):
  ```typescript
  const filteredItems = rawItems.filter((item) => {
    if (!searchQuery.trim()) return true;
    const q = searchQuery.toLowerCase();
    return (
      item.student.name.toLowerCase().includes(q) ||
      item.student.email.toLowerCase().includes(q)
    );
  });
  ```
- **Finding:** `rawItems` is derived from `enrollmentsData?.items`, which represents strictly the currently retrieved page (default 10 items). If a course has $>10$ enrollments across multiple pages, searching for a learner who is on page 2 while viewing page 1 will yield 0 results unless the instructor navigates to page 2.
- **Contrast with CSV Export:** CSV export (`handleExportCsv`, lines 114–133) fetches all pages iteratively up to 100/page before applying the search filter, ensuring full-dataset export.
- **Classification:** **Medium Severity Usability Defect / Accepted Limitation** (`DEF-P6.2-UX-01`).
- **Remediation Recommendation:** In a future work package (e.g., P6.3), add an optional `search` query parameter to backend endpoint `GET /api/v1/admin/courses/:id/enrollments` and push search filtering to the database query layer.

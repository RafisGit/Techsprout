## 1. Objective

Deliver high-fidelity, secure, and performant server-side PDF generation and downloading for student and admin invoices:
1. Provide a dedicated PDF generation and streaming engine that converts immutable stored invoice snapshots into clean, printable A4 PDF documents.
2. Ensure strict server-side authorization and IDOR protection: students may only download invoices they own (`invoice.studentId === req.user.id`), while administrators can access all invoices via RBAC.
3. Stream the generated PDF directly to the client with compliant `Content-Type: application/pdf` and deterministic `Content-Disposition: attachment; filename="TSP-INV-..."` headers.
4. Enforce strict financial snapshot immutability: never recalculate or re-query historical prices, coupons, or titles; faithfully preserve original monetary values even after an invoice is refunded.
5. Adhere to the single canonical BDT currency formatting rule (`BDT X,XXX.XX`, never `$`) and inclusive tax policy (zero synthetic VAT/tax claims).
6. Safeguard against abuse with per-user rate limiting (10 requests/minute) and comprehensive audit logging (`INVOICE_PDF_DOWNLOADED`).
7. Deliver a clean, responsive, and accessible "Download PDF" affordance in the student invoice view with loading and error states.

## 3. PDF Generation Architecture

The PDF generation architecture follows a lightweight, serverless-friendly, streaming pipeline:

```
[Student / Admin HTTP GET /api/v1/invoices/:id/pdf]
                      │
                      ▼
            [JwtAuthGuard + RBAC]
                      │
                      ▼
               [ThrottlerGuard] (10 req/min)
                      │
                      ▼
               InvoicesController
                      │
                      ▼
               InvoicesService.getInvoiceForPdf(id, user)
                      │
       ┌──────────────┴──────────────┐
       │ Check studentId === user.id │
       │ or user.role === 'admin'    │
       └──────────────┬──────────────┘
                      │
                      ▼
          InvoicePdfService.generateInvoicePdfStream(invoice)
                      │
           (PDFKit Document Instance)
                      │
                      ▼
            PassThrough Stream (StreamableFile)
                      │
                      ▼
     AuditService.record('INVOICE_PDF_DOWNLOADED')
                      │
                      ▼
[HTTP 200: Content-Type: application/pdf]
[Content-Disposition: attachment; filename="TSP-INV-...pdf"]
```

### Key Design Decisions:
1. **Lightweight `pdfkit`**: Installed `pdfkit` and `@types/pdfkit`. No headless browsers (Puppeteer/Chromium) or external C-libraries (wkhtmltopdf) required, ensuring low memory usage and full compatibility with the Render production environment.
2. **Direct Memory / Stream Pipe**: PDF bytes are piped directly into a Node.js `stream.PassThrough` returned via NestJS `StreamableFile`. No temporary files are written to disk, preventing disk exhaustion and race conditions.
3. **No Redundant Queries**: Only a single join between `invoices` and `orders` is executed. Unrelated catalog or user tables are never touched.

## 4. Invoice Data Source & Immutability

The PDF is generated **exclusively** from the authoritative, frozen snapshot stored in the `invoices` and `orders` database records:

| PDF Field | Database Source | Immutability Rule |
| :--- | :--- | :--- |
| **Invoice Number** | `invoices.invoice_number` | Authoritative frozen string |
| **Issued Date** | `invoices.created_at` | Immutable timestamp |
| **Order Number** | `orders.order_number` | Immutable transaction reference |
| **Student Name** | `orders.customer_name` | Frozen at checkout |
| **Student Email** | `orders.customer_email` | Frozen at checkout |
| **Line Item Title** | `invoices.course_title` | Frozen at purchase; never queries live course title |
| **Subtotal** | `invoices.subtotal` | Stored minor units (e.g. 500,000 cents) |
| **Discount** | `invoices.discount` | Stored minor units (e.g. 50,000 cents) |
| **Payable Total** | `invoices.payable` | Stored minor units (e.g. 450,000 cents) |
| **Currency** | `invoices.currency` | Stored ISO currency (`BDT`) |
| **Payment Method** | `orders.payment_method` | Stored gateway provider method |
| **Bank Tran ID** | `orders.bank_tran_id` | Student-visible provider reference |
| **Status** | `invoices.status` | Lifecycle status (`PAID`, `REFUNDED`, `VOID`) |

**Historical Accuracy Principle**: Even if the course price increases, discounts expire, or the course title changes in the catalog, the invoice PDF retains the exact historical financial snapshot captured at the moment of payment.

## 5. Authorization & IDOR Protection

Strict server-side validation is enforced in `InvoicesService.getInvoiceForPdf`:

```typescript
const isOwner = invoice.studentId === user.id;
const isAdmin = user.role === 'admin';

if (!isOwner && !isAdmin) {
  throw new ForbiddenException({
    code: 'FORBIDDEN',
    message: 'You are not authorized to access this invoice',
  });
}
```

### Security Vectors Verified:
- **Student A accessing Student B's invoice**: Returns HTTP 403 `FORBIDDEN`.
- **Manipulated path ID / UUID**: Validated by `ParseUUIDPipe` (returns 400 for malformed UUIDs).
- **Non-existent invoice ID**: Returns HTTP 404 `NOT_FOUND`.
- **Unauthenticated requests**: Blocked by `JwtAuthGuard` (returns 401 `UNAUTHORIZED`).
- **Admin Access**: Administrators can download any valid invoice via either the student or admin route.
- **No Token in URL**: The frontend uses Axios `responseType: 'blob'` with `Authorization: Bearer <token>` in HTTP headers; no tokens are passed in URL query parameters.

## 8. Money Formatting

All monetary figures in the PDF and frontend use the canonical money formatting logic from `@techsprout/contracts`:
- Standard: `formatMinorUnits(cents, 'BDT')` -> e.g. `BDT 1,000.00`

Both `formatMinorUnits` and `formatMoney` are exported from `@techsprout/contracts` and re-exported in `apps/web/src/lib/money.ts`.

## 10. Audit Logging

Every successful PDF generation is recorded in the immutable audit log:
- **Event**: `INVOICE_PDF_DOWNLOADED`
- **Actor ID**: Authenticated user's ID (`req.user.id`).
- **Target Type**: `INVOICE`
- **Target ID**: `invoice.id`
- **Metadata Logged**:
  - `invoiceId`: UUID of the invoice.
  - `invoiceNumber`: Unique invoice reference (e.g. `TSP-INV-2026-000101`).
  - `orderId`: Associated order UUID.
  - `orderNumber`: Associated order number.
  - `status`: Invoice status (`PAID` or `REFUNDED`).
  - `source`: Controller route (`STUDENT_PORTAL` or `ADMIN_FINANCE`).
  - `timestamp`: ISO-8601 download timestamp.
- **Zero Leakage**: Audit logs never record binary streams, SSLCommerz store passwords, gateway secrets, or session credentials.

## 17. Known Limitations

1. **Ephemeral Rendering**: Invoice PDFs are generated on-the-fly and streamed. They are not cached in Cloudflare R2 or AWS S3. Under expected traffic (< 10 downloads/min/user), CPU impact is negligible (< 15ms per invoice), but high concurrency workloads would benefit from a CDN cache layer in Phase 6.
2. **Language Support**: PDF text uses standard Helvetica/Helvetica-Bold fonts. Bengla script line items (if introduced in future phases) will require embedding a custom TrueType Unicode font (e.g. Noto Sans Bengali).

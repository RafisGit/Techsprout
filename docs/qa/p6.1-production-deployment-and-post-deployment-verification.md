## 12. Outbox, BullMQ and Event Safety

- **Queue & Worker Initialization:** Health probe confirms `redis: "up"`, indicating successful connection between the NestJS API container and `techsprout-redis`.
- **Worker Configuration:** Concurrency = 5, bounded retries = 3 with exponential backoff (1,000ms base delay), dead-letter retention with `removeOnFail: false`.
- **Transaction Decoupling:** In `OutboxService.emit()`, event enqueueing is wrapped in independent exception handling so that any queue latency or Redis error updates the outbox record to `FAILED` and **never rolls back business transactions** (orders, payments, enrollments, certificates).

## 6. Operator Instructions for Staging Deployment

The human operator should execute the following actions in the respective cloud provider dashboards:

### Step 1: Render Staging Blueprint Synchronization
1. Log in to the [Render Dashboard](https://dashboard.render.com).
2. Navigate to the **TechSprout Staging Workspace**.
3. Select the Blueprint instance managing `techsprout-api-staging` (associated with `render.staging.yaml`).
4. In the Blueprint settings:
   - Ensure the tracked branch is set to `release/p6.3-candidate`.
   - Click **Sync Blueprint** or **Apply Changes**.
5. **CRITICAL SAFETY INSPECTION ON PREVIEW:**
   - Verify that the preview proposes updating ONLY the Git branch of `techsprout-api-staging` from `release/p6.2-candidate` to `release/p6.3-candidate`.
   - **CONFIRM ZERO DESTRUCTIVE CHANGES:** The preview MUST NOT propose deleting, recreating, or resetting `techsprout-postgres-staging` or `techsprout-redis-staging`.
   - If any database recreation is indicated, **CANCEL IMMEDIATELY**.
6. Approve and trigger deployment for `techsprout-api-staging`.
7. **Monitor Build & Migration Execution:**
   - Render build command executes: `pnpm install ... && pnpm contracts build && pnpm api build`.
   - Render start command executes: `node apps/api/dist/database/migrate.js && node apps/api/dist/database/seed/seed.js && node apps/api/dist/main.js`.
   - Verify in the deploy logs that `0008_analytics_foundation.sql` runs and completes successfully (creating the 4 secondary indexes).
   - Confirm server starts on port 10000 and health check passes (`/api/v1/health` $\rightarrow$ 200).

### Step 2: Vercel Staging Deployment Configuration
1. Log in to the [Vercel Dashboard](https://vercel.com).
2. Navigate to project `techsprout-web-staging`.
3. In **Settings** $\rightarrow$ **Git**:
   - Update **Production Branch** (or tracking branch for staging) to `release/p6.3-candidate`.
4. Navigate to **Deployments** and trigger a new deployment from `release/p6.3-candidate`.
5. Monitor build: confirm Next.js Turbopack build finishes cleanly with all 32 routes compiled.

### Step 3: Trigger Automated Live Staging Smoke Tests
Once deployed, re-run verification probes to confirm:
- `GET /api/v1/instructor/analytics/overview` returns `HTTP 401 Unauthorized` (confirming route exists and requires auth).
- Authenticated instructor session accesses overview and course deep-dive.
- Roster server-side search functions across pages.
- Admin overview and student personal engagement load correctly.

## 5. Environment Isolation (Section 3)

### Declarative Separation in [`render.yaml`](file:///d:/Work/2026/techsprout-main/render.yaml)
1. **Database Separation:**
   - Production API binds `DATABASE_URL` via `fromDatabase: techsprout-postgres`.
   - Staging API binds `DATABASE_URL` via `fromDatabase: techsprout-postgres-staging`.
   - Production DB: `databaseName: techsprout`, `user: techsprout`.
   - Staging DB: `databaseName: techsprout_staging`, `user: techsprout_staging`.
2. **Redis Separation:**
   - Production API binds `REDIS_URL` via `fromService: techsprout-redis`.
   - Staging API binds `REDIS_URL` via `fromService: techsprout-redis-staging`.
   - Private network namespaces (`ipAllowList: []`) enforce perimeter isolation.
3. **Cross-Environment Protection:**
   - Staging does NOT possess credentials or network routes to production PostgreSQL or production Redis.
   - Live cloud verification of connections is blocked pending live staging container activation.

## 6. Session Isolation (Section 4)

1. **Independent Cryptographic Secrets:**
   - In `render.yaml`, both `techsprout-api` and `techsprout-api-staging` define:
     ```yaml
     - key: AUTH_SECRET
       generateValue: true
     ```
   - Render automatically provisions distinct 256-bit entropy keys for each service.
2. **Token Invalidation:**
   - Any session cookie minted by Staging presented to `https://techsprout-api.onrender.com` will fail HMAC signature verification and return `401 Unauthorized` (`INVALID_TOKEN`).
   - Any session cookie minted by Production presented to `https://techsprout-api-staging.onrender.com` will fail HMAC signature verification and return `401 Unauthorized` (`INVALID_TOKEN`).
3. **Cookie Hygiene:**
   - `HttpOnly: true`, `Secure: true`, `SameSite: Lax`. Secrets and keys are never exposed in responses or browser storage.

## 1. Scope Implemented

Phase P5.4.4 delivers the complete end-to-end student checkout and payment experience for paid courses, fully respecting server-authoritative financial invariants and integrating with the P5.3 Core Payment Engine, P5.4.1 Invoices, and P5.4.3 Coupons.

### Key Deliverables:
1. **Paid-Course "Buy Now" CTA**: Dynamic CTA on course details page (`/courses/[slug]`) directing unauthenticated users to login with post-auth redirect, and authenticated users to dedicated checkout. Free courses retain the existing self-enrollment flow.
2. **Dedicated Student Checkout Route**: `/checkout/[slug]` with authoritative order summary, course snapshot, live coupon input, read-only preview, and double-click prevention.
3. **Server-Authoritative Pricing & Revalidation**: Total payable, subtotal, and discounts are derived strictly on the backend. Frontend prices are presentation-only.
4. **Coupon Input & Preview**: Read-only validation via `POST /api/v1/coupons/validate` with normalized uppercase codes and instant breakdown in BDT.
5. **Order Creation Integration**: Revalidates course status and coupons, locks coupon row with pessimistic locking (`FOR UPDATE`), and creates historical order/item snapshots.
6. **Payment Initiation & Boundaries**: Integrates with `POST /api/v1/payments/initiate` enforcing gateway thresholds (`10.00 BDT <= payable <= 500,000.00 BDT` or `0 BDT`).
7. **Zero-Payable Fulfillment Flow**: 100% discount coupons bypass SSLCommerz gateway entirely, fulfilling internally into `PAID` order, active enrollment, consumed coupon, and official tax invoice.
8. **SSLCommerz Hosted Redirect**: Seamless browser navigation to SSLCommerz hosted payment gateway for standard paid orders.
9. **Untrusted Return Resolution**: Payment return pages (`/orders/[orderId]/success`, `/orders/[orderId]/cancelled`, `/orders/[orderId]/failure`) never trust URL parameters; order state is verified authoritatively against TechSprout PostgreSQL database.
10. **Bounded Status Polling**: Handles asynchronous gateway clearing with bounded polling (max 12 attempts over 30s) for `PAYMENT_PROCESSING` state, preventing infinite loops.
11. **Invoice Availability**: Paid orders expose official invoice ID, linking directly to `/invoices/[id]` for private viewing and printing.
12. **Enrollment Access**: "Start Learning" CTA links to `/learn/[courseSlug]` only when backend verifies order status is `PAID` and enrollment is `ACTIVE`.
13. **Comprehensive Test Suites**:
    - Frontend suite: `apps/web/src/__tests__/checkout-flow.spec.ts` (21 tests).
    - API Integration suite: `apps/api/src/test/checkout-integration.spec.ts` (14 tests).

## 3. Buy Now Integration

On `/courses/[slug]`:
- **Paid Courses (`course.price > 0`)**:
  - Displays tuition formatted in BDT (e.g. `3,500 BDT`).
  - Action button: **"Buy Now"** (or **"Log in to purchase"** if unauthenticated).
  - Navigation: Redirects to `/checkout/[slug]` (or `/login?redirect=/checkout/[slug]`).
- **Free Courses (`course.price === 0`)**:
  - Displays **"Free"**.
  - Action button: **"Enroll Now"** (or **"Log in to enroll"**).
  - Executes immediate self-enrollment via `POST /api/v1/enrollments` and redirects directly to curriculum at `/learn/[slug]`.
- **Enrolled Courses**:
  - Displays **"Continue Learning"** / **"View Course"** with progress indicator.

## 4. Coupon Preview

- Endpoint: `POST /api/v1/coupons/validate`
- Request: `{ code: string, courseId: string }`
- **Read-Only Guarantee**:
  - Creates 0 orders.
  - Creates 0 redemptions.
  - Does not increment `redemptionCount`.
  - Does not modify database rows.
- Code is normalized case-insensitively (`welcome10` -> `WELCOME10`).
- Calculates minor integer unit discount (`discountCents`) and preview payable (`payableCents`).
- Handles coupon validation errors cleanly with domain-specific alerts (`COUPON_EXPIRED`, `COUPON_MIN_ORDER_NOT_MET`, `COUPON_USAGE_LIMIT_REACHED`, `COUPON_USER_LIMIT_REACHED`).

---

## 5. Server-Authoritative Order Creation

Order creation via `POST /api/v1/orders`:
- **Server Price Authority**: Client-submitted `price`, `subtotal`, `discount`, and `payable` fields are rejected by strict Zod contract schema.
- **Authoritative Revalidation**: Coupon validity, active dates, scope (course-specific vs. global), minimum order requirements, and per-user limits are rechecked against active database records.
- **Pessimistic Row Locking**: Acquires `SELECT ... FOR UPDATE` on the coupon row inside an atomic transaction, incrementing `redemptionCount` and inserting `coupon_redemptions` in `RESERVED` status.
- **Snapshot Persistence**: Order items freeze `unitPriceCents`, `courseTitle`, and discounts as immutable snapshots.

---

## 6. Payment Initiation

- Endpoint: `POST /api/v1/payments/initiate`
- Request: `{ orderId: string }`
- Re-verifies student ownership (`order.studentId === authenticatedUser.id`).
- Verifies order expiration (`order.expiresAt > now()`).
- Transitions order state to `PAYMENT_PROCESSING`.
- Enforces official SSLCommerz V4 boundary invariants:
  - `payableCents === 0`: Internal zero-payable bypass.
  - `1 <= payableCents < 1000`: Rejected with `PAYMENT_AMOUNT_BELOW_GATEWAY_MINIMUM` (10.00 BDT minimum).
  - `1000 <= payableCents <= 50,000,000`: Gateway initiation allowed.
  - `payableCents > 50,000,000`: Rejected with `PAYMENT_AMOUNT_ABOVE_GATEWAY_MAXIMUM` (500,000.00 BDT maximum).

---

## 7. Zero-Payable Flow

When a coupon reduces payable tuition to `0 BDT` (`payableCents === 0`):
1. Payment initiation bypasses SSLCommerz gateway completely.
2. Executes atomic internal fulfillment:
   - Order marked `PAID`.
   - Enrollment marked `ACTIVE`.
   - Coupon redemption marked `CONSUMED`.
   - Tax invoice issued in `PAID` status with `$0` payable.
3. Gateway URL returns internal redirect URL: `/orders/[orderId]/success`.
4. Browser navigates directly to success page without external payment provider redirects.

---

## 8. SSLCommerz Redirect

For transactions between 10.00 BDT and 500,000.00 BDT:
1. Backend invokes SSLCommerz v4 API (`/gwprocess/v4/api.php`) with store credentials and transaction parameters.
2. Returns authoritative `gatewayUrl` (`GatewayPageURL`).
3. Browser performs full-page redirection: `window.location.href = res.gatewayUrl`.
4. Store password and provider secrets are never exposed to client code, audit logs, or browser responses.

---

## 9. Return-Page Security

- The browser return callback sends parameters such as `tran_id`, `val_id`, and `status`.
- **Zero Trust on Query Strings**: The frontend completely ignores URL query parameters for concluding transaction success.
- **Mandatory Server Verification**: The frontend queries `GET /api/v1/orders/[orderId]` with authenticated session cookies.
- Cross-student access is blocked with HTTP 403 `ORDER_ACCESS_DENIED`.

---

## 10. Order-Status Polling

On `/orders/[orderId]/success`:
- If `order.status === 'PAYMENT_PROCESSING'` or `'PENDING'`:
  - UI displays: *"Verifying your payment with the bank..."*
  - Initiates bounded polling every 2.5 seconds.
  - Max polling window: 12 attempts (30 seconds maximum).
  - Prevents infinite polling loops.
  - On timeout: Displays *"Payment Verification Still in Progress"* with manual *"Check Status Again"* retry button.
  - When status updates to `PAID`: Stops polling, shows confirmation banner, invoice link, and Start Learning button.

---

## 11. Invoice Access

- Paid orders expose `order.invoiceId`.
- Success page provides direct link: *"View Official Tax Invoice"* -> `/invoices/[invoiceId]`.
- Invoice page (`/invoices/[id]`):
  - Fetches authoritative data from `GET /api/v1/invoices/:id`.
  - Displays official receipt with line items, subtotal, discounts, bank transaction ID, student details, and BDT totals.
  - Includes a clean printable layout (`window.print()`) with print CSS media styles.

---

## 12. Enrollment Access

- Enrollment is activated strictly on the backend upon payment validation or zero-payable fulfillment.
- The browser contains no endpoint or logic for client-side enrollment activation.
- "Start Learning" button is shown on the success page only when `order.status === 'PAID'`, linking to `/learn/[courseSlug]`.

---

## 13. Error & Loading UX

- **Button State**: CTA displays loading spinner and progress labels (*"Creating Order..."*, *"Redirecting to SSLCommerz..."*, *"Completing Free Enrollment..."*).
- **Double-Click Protection**: Buttons are disabled during active mutations.
- **Domain Errors**: Displays actionable error banners for expired coupons, exhausted coupons, below-minimum orders, and declined payments.

## 14. Security Testing

| Threat Vector | Defense Mechanism | Test Case |
|---|---|---|
| Client injects fake course price | Schema rejects extra fields; backend calculates from DB | `checkout-integration.spec.ts:21` |
| Client injects fake coupon discount | Strict Zod schema; backend derives discount from DB rules | `checkout-integration.spec.ts:22` |
| Stale coupon preview applied | Revalidated under pessimistic lock at order creation | `checkout-integration.spec.ts:24` |
| Below gateway minimum (5 BDT) | Rejected before gateway with 400 error | `checkout-integration.spec.ts:28` |
| Above gateway maximum (600,000 BDT) | Rejected before gateway with 400 error | `checkout-integration.spec.ts:29` |
| Fake success query params | Ignored; state loaded from DB | `checkout-flow.spec.ts:16`, `checkout-integration.spec.ts:30` |
| Cross-student order inspection | Ownership check enforces 403 Forbidden | `checkout-flow.spec.ts:17` |
| Cross-student invoice inspection | Ownership check enforces 403 Forbidden | `invoices.spec.ts` |
| Client activates enrollment directly | Only backend transaction activates enrollment | `checkout-integration.spec.ts:32, 33` |

## 19. Known Limitations

2. **Subscriptions**: Recurring subscription payments are not supported by the one-time checkout flow.

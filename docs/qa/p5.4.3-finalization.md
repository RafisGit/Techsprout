## 1. Scope

P5.4.3 implements the coupon management subsystem and validation engine as specified by the frozen P5.4 architecture sequence.

### Included:
1. Shared coupon TypeScript contracts and Zod validation schemas (`@techsprout/contracts`).
2. Public / Student read-only coupon validation and preview service (`POST /api/v1/coupons/validate`).
3. Admin coupon CRUD API:
   - `GET /api/v1/admin/coupons` (paginated listing with active status, code search, and course filtering)
   - `POST /api/v1/admin/coupons` (create new coupon with code normalization and duplicate rejection)
   - `GET /api/v1/admin/coupons/:id` (detail inspection including course title and usage statistics)
   - `PATCH /api/v1/admin/coupons/:id` (safe mutation of coupon parameters; guards against lowering usageLimit below current redemptions)
   - `DELETE /api/v1/admin/coupons/:id` (soft-disable via `isActive = false`; hard database deletion is forbidden)
4. Coupon lifecycle and scope enforcement (course-specific vs. global catalog).
5. Integer arithmetic discount calculation engine (percentage with optional cap, fixed amount) with minor unit precision (cents).
6. Compatibility with existing `RESERVED` / `CONSUMED` / `RELEASED` redemption semantics and pessimistic locking during order creation.
7. End-to-end integration and security test suite (`coupons.spec.ts`, 37 test cases).

### Excluded (Deferred to subsequent phases):

## 2. Existing Coupon Schema

P5.4.3 strictly utilizes the existing schema defined in `apps/api/src/database/schema/coupons.ts` (persisted via `0004_payment_admin_subsystem.sql` in P5.2). **Zero new database migrations were introduced.**

### Table: `coupons`
- `id`: UUID (Primary Key, default `gen_random_uuid()`)
- `code`: VARCHAR(50) (Unique, case-insensitive index `idx_coupons_code`)
- `discount_type`: `coupon_discount_type` enum (`PERCENTAGE`, `FIXED_AMOUNT`)
- `discount_value`: INTEGER (Percentage 1–100, or fixed BDT cents)
- `min_order_amount_cents`: INTEGER (Optional minimum order subtotal requirement)
- `max_discount_amount_cents`: INTEGER (Optional ceiling for percentage discounts)
- `course_id`: UUID (Nullable foreign key referencing `courses.id`; `NULL` = global)
- `usage_limit`: INTEGER (Nullable total redemption ceiling across all users)
- `per_user_limit`: INTEGER (Default 1, maximum redemptions per authenticated student)
- `redemption_count`: INTEGER (Default 0, total active reserved + consumed redemptions)
- `is_active`: BOOLEAN (Default `true`)
- `starts_at`: TIMESTAMP WITH TIME ZONE (Default `now()`)
- `expires_at`: TIMESTAMP WITH TIME ZONE (Nullable)
- `created_by`: UUID (Foreign key referencing `users.id`)
- `created_at`: TIMESTAMP WITH TIME ZONE (Default `now()`)
- `updated_at`: TIMESTAMP WITH TIME ZONE (Default `now()`)

### Table: `coupon_redemptions`
- `id`: UUID (Primary Key)
- `coupon_id`: UUID (Foreign key referencing `coupons.id`)
- `user_id`: UUID (Foreign key referencing `users.id`)
- `order_id`: UUID (Foreign key referencing `orders.id`)
- `status`: `redemption_status` enum (`RESERVED`, `CONSUMED`, `RELEASED`)
- `discount_cents`: INTEGER
- `reserved_at`: TIMESTAMP WITH TIME ZONE (Default `now()`)
- `consumed_at`: TIMESTAMP WITH TIME ZONE (Nullable)
- `released_at`: TIMESTAMP WITH TIME ZONE (Nullable)

## 4. Public Validation API

### Endpoint: `POST /api/v1/coupons/validate`
- **Access**: `@Public()` with optional session extraction (via `req.cookies` session resolution).
- **Guarantees**:
  1. **Strict Server-Side Authority**: Frontend-provided price, subtotal, discount, or payable amounts are ignored. The server fetches the authoritative course price directly from PostgreSQL (`courses.price` joined with active `categories.isActive`).
  2. **Read-Only Operation**: Never creates orders, never inserts into `coupon_redemptions`, never increments `redemptionCount`, and never alters coupon state.
  3. **Course Status Enforcement**: Verifies the course exists, is published (`status = 'PUBLISHED'`), is public (`visibility = 'PUBLIC'`), and its category is active.
  4. **Per-User Limit Check**: If an authenticated session is detected, queries existing `RESERVED` and `CONSUMED` redemptions for `(userId, couponId)`. If the limit is reached, validation fails with `COUPON_USER_LIMIT_REACHED`. Unauthenticated users can preview global/course rules, while per-user enforcement occurs authoritatively at checkout / order creation.

## 5. Admin CRUD API

All administrative endpoints require authentication, `RolesGuard`, and `@Roles('admin')`. Non-admin requests receive `403 Forbidden`.

- **`GET /api/v1/admin/coupons`**:
  - Paginated list (`page`, `limit`).
  - Filters by `isActive`, `search` (case-insensitive code prefix/contains), and `courseId`.
  - Joins `courses` table to enrich output with `courseTitle`.
- **`POST /api/v1/admin/coupons`**:
  - Normalizes code (`.trim().toUpperCase()`).
  - Checks for duplicate codes (409 Conflict: `COUPON_CODE_ALREADY_EXISTS`).
  - Verifies target course existence and publication status if `courseId` is provided.
  - Records administrative audit log (`COUPON_CREATED`).
- **`GET /api/v1/admin/coupons/:id`**:
  - Returns coupon details with associated course title and live redemption counts.
- **`PATCH /api/v1/admin/coupons/:id`**:
  - Permitted fields: `minOrderAmountCents`, `maxDiscountAmountCents`, `usageLimit`, `perUserLimit`, `startsAt`, `expiresAt`, `isActive`.
  - Invariant guard: If `usageLimit` is being updated and is lower than existing `coupon.redemptionCount`, rejects with 400 Bad Request (`COUPON_INVALID`).
  - Validates date timeline consistency (`startsAt < expiresAt`).
  - Records audit log (`COUPON_UPDATED`).
- **`DELETE /api/v1/admin/coupons/:id`**:
  - Implements **Soft Delete** (`isActive = false`).
  - Does NOT delete database rows, preserving audit logs, order references, and redemption history.
  - Records audit log (`COUPON_DEACTIVATED`).

## 6. Discount Calculation

Discounts are calculated using deterministic integer arithmetic in minor currency units (BDT cents) via `calculateDiscountCents`:

1. **PERCENTAGE**:
   - `rawDiscount = Math.round((subtotalCents * discountValue) / 100)`
   - If `maxDiscountAmountCents` is configured: `discountCents = Math.min(rawDiscount, maxDiscountAmountCents)`.
2. **FIXED_AMOUNT**:
   - `discountCents = discountValue` (stored in cents).
3. **Subtotal Cap**:
   - `discountCents = Math.min(subtotalCents, discountCents)`
4. **Payable Amount**:
   - `payableCents = Math.max(0, subtotalCents - discountCents)`
5. **Zero-Payable (100% Discount)**:
   - When `payableCents === 0`, the transaction qualifies for the existing P5.3 zero-payable fulfillment pipeline (direct enrollment without SSLCommerz invocation).

## 7. Course vs. Global Scope

- **Course-Scoped (`courseId IS NOT NULL`)**:
  - Coupon applies **only** when `order.courseId === coupon.courseId`.
  - Attempting to validate or redeem against any other course is rejected with `COUPON_COURSE_MISMATCH` (HTTP 400).
- **Global-Scoped (`courseId IS NULL`)**:
  - Coupon applies to any eligible catalog course subject to minimum order and validity rules.

---

## 8. Usage & Per-User Constraints

1. **Global Usage Limit**:
   - Invariant: `active_redemptions + consumed_redemptions <= usage_limit`.
   - Tracked via `coupons.redemption_count`.
   - Preview checks: `usageLimit != null && redemptionCount >= usageLimit` → `COUPON_USAGE_LIMIT_REACHED`.
   - Reservation enforcement: `OrdersService.createOrder` acquires a row-level lock (`SELECT ... FOR UPDATE` on `coupons`) inside an atomic transaction, preventing concurrent race-condition oversubscription.
2. **Per-User Limit**:
   - Invariant: `COUNT(coupon_redemptions WHERE userId = studentId AND status IN ('RESERVED', 'CONSUMED')) < perUserLimit`.
   - `RELEASED` redemptions (e.g. from expired or cancelled orders) restore user allowance and decrement `redemption_count`.

## 10. Security & Input Sanitization

1. **Server Authority**: Client-supplied prices, discounts, and payables are ignored entirely.
2. **Code Normalization**: Codes are trimmed and capitalized (`"  welcome10  "` → `"WELCOME10"`), preventing case-variation bypass.
3. **Secret Redaction**: Response DTOs never expose sensitive system configuration, payment gateway credentials, or internal user password hashes.
4. **RBAC Isolation**: Admin coupon routes verify `@Roles('admin')`; student sessions receive 403 Forbidden.
5. **Brute-Force & Integrity**: Rate-limiting and standardized error responses prevent leakage of internal stack traces.

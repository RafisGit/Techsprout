## 1. Executive Summary

During live staging cloud provisioning for Phase 6.1, the Render Cloud Blueprint sync failed with the following cloud provider rejections:
```text
techsprout-postgres-staging
→ cannot have more than one active free tier database

techsprout-redis-staging
→ cannot have more than 1 free tier Key Value instance
```

### Key Findings
1. **Root Cause Diagnosis:**
   Render strictly enforces account/workspace-level quota limits on free-tier resources:
   - Exactly **1 active free PostgreSQL instance** per Render workspace.
   - Exactly **1 active free Key Value (Redis) instance** per Render workspace.
   When both Production (`techsprout-postgres`, `techsprout-redis`) and Staging (`techsprout-postgres-staging`, `techsprout-redis-staging`) were declared inside a single combined `render.yaml`, Render Cloud rejected the multi-instance provisioning because the production workspace had already consumed its free quota.

2. **Core Remediation Principle:**
   - **DO NOT upgrade production to paid tiers.**
   - **DO NOT delete production resources.**
   - **DO NOT replace production resources.**
   - **DO NOT share production databases or Redis.**
   - **DO NOT modify application code.**

3. **Architectural Resolution:**
   The monolithic `render.yaml` was split into two independent Blueprint specifications:
   - [`render.yaml`](file:///d:/Work/2026/techsprout-main/render.yaml): Manages **ONLY** production resources (`techsprout-api`, `techsprout-postgres`, `techsprout-redis`) in the **Production Workspace**.
   - [`render.staging.yaml`](file:///d:/Work/2026/techsprout-main/render.staging.yaml): Manages **ONLY** staging resources (`techsprout-api-staging`, `techsprout-postgres-staging`, `techsprout-redis-staging`) in a dedicated **Staging Hobby Workspace**.

## 3. Blueprint Separation

### Production Blueprint: `render.yaml`
Manages exclusively the production environment:
- **Services:**
  - `techsprout-api` (`type: web`, `plan: free`, `region: oregon`)
  - `techsprout-redis` (`type: keyvalue`, `plan: free`, `region: oregon`)
- **Databases:**
  - `techsprout-postgres` (`databaseName: techsprout`, `user: techsprout`, `plan: free`, `region: oregon`)
- **Integrity Guarantee:**
  - Zero references to staging resources.
  - Zero configuration changes.
  - Byte-for-byte identical to the verified production deployment.

### Staging Blueprint: `render.staging.yaml`
Manages exclusively the staging environment in Render Workspace B:
- **Services:**
  - `techsprout-api-staging` (`type: web`, `plan: free`, `region: oregon`):
    - `NODE_ENV: staging`
    - `PORT: 10000`
    - `DATABASE_URL`: `fromDatabase: name: techsprout-postgres-staging, property: connectionString`
    - `REDIS_URL`: `fromService: type: keyvalue, name: techsprout-redis-staging, property: connectionString`
    - `AUTH_SECRET`: `generateValue: true` (Independent 256-bit entropy secret)
    - `WEB_ORIGIN`: `https://staging.techsprout-web.vercel.app,https://techsprout-web-staging.vercel.app`
    - `WEB_PUBLIC_ORIGIN`: `https://staging.techsprout-web.vercel.app`
    - `SSLCOMMERZ_IS_SANDBOX`: `"true"`
    - `SSLCOMMERZ_BASE_URL`: `https://sandbox.sslcommerz.com`
    - `RESEND_FROM_EMAIL`: `staging-notifications@techsprout.io`
  - `techsprout-redis-staging` (`type: keyvalue`, `plan: free`, `region: oregon`):
    - `ipAllowList: []`
    - `maxmemoryPolicy: noeviction`
- **Databases:**
  - `techsprout-postgres-staging` (`databaseName: techsprout_staging`, `user: techsprout_staging`, `plan: free`, `region: oregon`, `postgresMajorVersion: 16`)
- **Integrity Guarantee:**
  - Zero references to production resources (`techsprout-api`, `techsprout-postgres`, `techsprout-redis`).
  - Completely self-contained dependency graph.

## 4. Why Production Remains Untouched

1. **No Shared Infrastructure:**
   - Staging does not share CPU, memory, database clusters, or Redis instances with production.
   - Staging migration execution (`node apps/api/dist/database/migrate.js`) targets only `techsprout_staging`.
2. **Zero Ingress/Egress Crossover:**
   - Private Redis instances use empty allowlists (`ipAllowList: []`), which restricts access to the private network namespace of the owning workspace.
   - Staging containers cannot reach production Redis. Production containers cannot reach staging Redis.
3. **Session & Cookie Partitioning:**
   - Independent `AUTH_SECRET` generation ensures JWT signature validation between environments is impossible (always `401 Unauthorized`).
   - Browser origin scoping separates `techsprout-web.vercel.app` and `staging.techsprout-web.vercel.app`.
4. **Payment Isolation:**
   - Staging defaults to sandbox mode; production payment credentials remain unreferenced.

## 6. Deployment & Manual Dashboard Instructions

To complete the staging environment provisioning on Render Cloud without impacting production:

### Step 1: Create or Select Render Hobby Workspace B
1. Log in to the [Render Dashboard](https://dashboard.render.com).
2. Click the workspace selector in the top-left navigation.
3. Select an existing secondary Hobby workspace or click **"Create New Workspace"** (e.g. `techsprout-staging`).

### Step 2: Create Staging Blueprint Instance
1. In the selected Staging Workspace, navigate to **Blueprints**.
2. Click **"New Blueprint Instance"**.
3. Connect the repository `RafisGit/Techsprout` (branch `main`).
4. In the **Blueprint Spec Path** field, change the default from `render.yaml` to:
   ```text
   render.staging.yaml
   ```
5. Click **"Apply"** / **"Approve"**.

### Step 3: Verify Resource Creation
Render Cloud will provision within the staging workspace:
1. `techsprout-postgres-staging` (PostgreSQL 16 Free)
2. `techsprout-redis-staging` (Key Value Free)
3. `techsprout-api-staging` (Web Service Free)

Once deployed, probe the health check endpoint:
```bash
GET https://techsprout-api-staging.onrender.com/api/v1/health
```
Expected response:
```json
{
  "status": "ok",
  "environment": "staging",
  "services": {
    "database": "up",
    "redis": "up"
  }
}
```

### Step 4: Map Vercel Staging Frontend
1. In the Vercel Dashboard, navigate to the `techsprout-web` project.
2. In **Settings -> Domains**, assign `staging.techsprout-web.vercel.app`.
3. Set environment variable `NEXT_PUBLIC_API_URL=https://techsprout-api-staging.onrender.com`.

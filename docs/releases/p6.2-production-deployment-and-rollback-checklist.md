## 4. Rollback Plan

If a critical blocker, data corruption, or severe availability regression occurs, execute the following rollback protocol:

### Trigger Conditions:
1. REST API startup failure or persistent health probe failure (`HTTP 500/503`).
2. Database migration failure causing unrecoverable PostgreSQL errors.
3. Widespread authentication failure locking users out of both web and API.
4. Financial calculation regression affecting checkout or refund workflows.

### Rollback Steps:

#### Phase 1: Immediate Web App Rollback (Vercel)
Vercel allows instant rollbacks with zero build delay:
1. Open Vercel Dashboard $\rightarrow$ Project `techsprout-web` $\rightarrow$ Deployments.
2. Locate the previous stable production deployment (commit `d67d8ee`).
3. Click `...` $\rightarrow$ **Instant Rollback (Promote to Production)**.
4. Verify `https://techsprout-web.vercel.app` is restored within 10 seconds.

#### Phase 2: REST API Rollback (Render)
1. In the local repository:
   ```bash
   git checkout main
   git revert -m 1 HEAD --no-edit # Reverts the P6.2 promotion merge commit
   git push origin main
   ```
2. Render detects the push to `main` and automatically builds and deploys the reverted commit (`d67d8ee`).
3. Alternatively, in Render Dashboard: click `Manual Deploy` $\rightarrow$ `Deploy a specific commit` $\rightarrow$ enter `d67d8eed0ed570e1e347e7952b9ae0cc80fbb38b`.

#### Phase 3: Database Compatibility Assessment
- **Migration `0007_instructor_platform_foundation.sql` is strictly forward-compatible and additive:**
  - It creates `course_review_requests` and `instructor_profiles`.
  - It adds `IN_REVIEW` enum value to `course_status`.
  - It adds `course_review_status` enum.
  - It does NOT remove or rename any existing columns or tables from P1–P6.1.
- Because P6.1 code ignores `course_review_requests` and `instructor_profiles`, the database schema remains 100% backward-compatible with the P6.1 API without requiring a DDL rollback.

#### Phase 4: Incident Post-Mortem & Incident Logging
1. Record error logs, Render container metrics, and Sentry reports.
2. Inform stakeholders and engineering leadership.
3. Re-open candidate investigation on `release/p6.2-candidate`.
